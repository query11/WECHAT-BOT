# 微信助手

> 本文保留详细行为说明及历史维护记录；首次安装请先阅读[快速开始](../QUICKSTART.md)。本机路径已改为示例，历史验证结论只代表当时环境。

通过个人微信指挥 Windows 本机的 Claude Code，支持文件处理、应用控制、屏幕交互、会议和提醒。Python 后台通过 iLink 长轮询收发消息；托盘运行中心展示实际连接与任务状态。

## 日常使用

新增 [定时任务管理](../features/功能改进-定时任务.md)：创建一次性或每天重复的微信提醒/自动任务，核对后保存；支持编辑、暂停、恢复、最近触发和任务记录入口。

新增 [本机文件任务](../features/功能改进-本机文件任务.md)：在电脑拖入或选择文件，选模板或直接填写要求，预览确认后保存输入副本并排队；明确选择“文件留本机、摘要发微信”或同时发送新结果文件。

新增 [结果继续修改](../features/功能改进-结果继续修改.md)：从结果或任务记录选择文件/文字回复，填写修改要求并核对；确认后保存旧版本副本、新建关联任务，版本列表可继续选择后续结果。

新增 [任务工作台与后续安排](../features/功能改进-任务工作台.md)：首页突出任务和结果，集中显示待恢复、待核对、发送未确认及附件待处理事项，直接定位对应记录；无文件结果和失败结果显示适合的查看入口。

新增 [阶段进度与界面记忆](../features/功能改进-阶段进度与界面记忆.md)：当前任务显示实际处理阶段、总耗时和阶段耗时；运行中心、任务记录、任务模板、快捷任务会记住窗口尺寸，以及适用的列宽、状态筛选和上次页签。

新增 [常用模板、附件核对与结果卡片](../features/功能改进-快捷模板与附件核对.md)：可固定常用模板，核对本次输入和输出位置后从电脑确认运行；附件核对窗口支持移出选错文件、处理缺失记录和确认清单；任务结束后运行中心展示摘要、检查结论和文件打开入口。

新增 [模板窗口与任务详情](../features/功能改进-模板窗口与任务详情.md)：运行中心“常用入口”右上角可打开“任务模板”，在电脑上新建、修改、复制和删除模板；已结束的任务可另存模板草稿。任务记录先展示摘要与文件，再按页签查看完整回复、输入与模板、检查结果；操作按钮显示具体动作和不可用原因。

新增 [附件对话与桌面任务操作](../features/功能改进-任务操作简化.md)：说“开始收集附件”，发齐后说“发完了，任务要求”，核对清单再“确认执行这批附件”；未确认批次可补传缺失文件、移除失败记录。桌面任务记录支持搜索、筛选和直接恢复、取消排队、人工核对等操作。本机加载情况见 [可靠性检查与验收](../testing/可靠性检查与验收.md)；已有任务记录窗口需关闭后重新打开。

任务产物、附件批次和任务模板的列表会附上填好编号的独立操作指令，可直接复制到微信；需要补充任务说明的操作仍需填写正文。本地临时副本清理失败不会覆盖文件发送回执，后台启动时会有界回收明确登记的闲置副本。当前验证范围与手机待测项目见 [可靠性检查与验收](../testing/可靠性检查与验收.md)。

1. 登录 Windows 后自动在托盘待机，也可双击 `微信助手.bat` 打开。
2. 在微信直接发 **开始对话**：一步唤醒助手并进入免前缀对话，然后发任务。
3. 忙完发 **结束对话**：退出对话并回到待机。若任务或附件仍在处理，会停止接收新任务，收尾后自动待机；再次“开始对话”可取消自动待机。

也支持“开启会话”“进入聊天模式”“打开对话”、`/on`、`/chat`；结束可说“退出聊天”“关闭会话”、`/off`、`/end`。旧的“启动助手／停止助手”和 `/wake`、`/standby` 保留。含其他任务的复合句不会被当成唤醒指令执行。

空闲超时只退出免前缀对话，需重新说“开始对话”继续；主动说“结束对话”才回到待机。待机不执行新消息或下载附件，已设置的提醒仍会通知。

## 桌面固定记忆

本机桌面是 **`C:\Users\your-name\Desktop`**，已核对 Windows 特殊文件夹设置和目录存在性。

记忆保存在 [BOT_MEMORY.md](../../BOT_MEMORY.example.md)，通过 `config.json` 的 `bot_memory_file` 配置注入每次 Claude 调用。它独立于聊天记录，重启、`/new` 和会话过期都不会清除。更新记忆文件后下一次调用生效；不要向其中写入密钥或令牌。

## 托盘与控制

- 蓝色气泡：在线待机；绿色：已唤醒；黄色：连接或重连；红色：需要处理；灰色：后台停止。
- 双击托盘打开运行中心；关闭窗口仍在托盘。菜单“退出程序”才关闭后台，此时微信无法唤醒。
- 窗口支持唤醒、待机、停止当前任务、重启服务和打开日志。
- 看到“代码已更新，重启后生效”，等任务、队列和附件处理完成后点“重启服务”；托盘脚本更新需“退出程序”后重开 `微信助手.bat`。版本约每 60 秒检查一次，纯文档修改不触发；悬停“服务维护”说明或重启按钮可看版本诊断与启动时提交号。“版本状态未知”不代表最新版或连接失败，具体含义见 [托盘运行中心说明](托盘运行中心说明.md)。
- 只息屏仍可使用；睡眠、休眠或关机会暂停服务。

## 安装与维护

依赖 Windows、Python 3.10+ 和 Claude Code CLI；扫码绘制二维码可选安装 `segno`。界面使用 Windows 自带 WinForms。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start_wechat.ps1 -Login
powershell -NoProfile -ExecutionPolicy Bypass -File .\install_autostart.ps1
```

配置登录和白名单后再使用。自启动是当前用户登录启动，并非登录前系统服务。`standby_on_start: true` 启用上述一体化唤醒；关闭该配置后保留旧版独立前缀和对话模式。

```powershell
python tools/verify.py --suite offline
python tools/verify.py --suite integration
python -m unittest tests.selftest_standby tests.selftest_memory tests.selftest_runtime tests.selftest_reliability
python -m unittest tests.selftest_task_journal tests.selftest_result_feedback tests.selftest_quick_status
```

可选：`powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\install_hooks.ps1` 装一个 pre-commit 钩子，提交前按固定清单跑一遍快速子集（支持中文文件名，删除或重命名代码也会检查；只改了文档的提交会跳过，`git commit --no-verify` 可临时绕过）。它只挡住明显被改坏的地方，不替代上面的全量自测。最近一次验证的项数以 [可靠性检查与验收](../testing/可靠性检查与验收.md) 顶部记录为准。

统一验证入口：`python tools/verify.py --list` 会列出每个套件的性质与前置条件；`--suite quick`（提交钩子的快速子集）、`--suite offline`（旧入口 `selftest.py`、快速子集、代码身份与验证入口专项，三项分别记录）、`--suite integration`（Windows 进程隔离集成测试，必须显式点名，不会默认启动真实业务、浏览器或用户程序）。报告与日志写在 `.runtime/verification/<本轮标识>/`，包含提交号、是否有未提交改动、实际命令、开始时间、耗时、退出码、每个套件的通过／失败／跳过与日志路径。每次子进程使用独立结果文件，复用 `--label` 不会沿用上次结果；异常退出或超时不能被成功 JSON 覆盖。通过数量取真实成功事件，跳过与预期失败另记。被请求的套件出现失败、超时、起不来或一条有效用例都没跑时整体返回非零并写明原因；检查条目数与测试用例数是两种单位，不能相加，也不代表手机实机行为已验收。

离线测试不代替真实微信操作。普通任务和附件队列仍在内存，重启前先查看任务；异常重启后应先确认执行结果，再决定是否重发。

### 微信接口 SSL 断开与系统代理

若窗口持续黄色，日志出现 `SSL: UNEXPECTED_EOF_WHILE_READING`，不代表程序已退出或一定是登录过期。2026-09-29 的排查发现 Windows 系统代理 `127.0.0.1:7897` 会截断 iLink 的 TLS；相同地址经系统代理失败、直连可正常完成 HTTPS。

当前版本对官方 `ilinkai.weixin.qq.com` 的 API 请求直接连接，保持证书校验；其他自定义 API 地址仍使用原有代理策略。未修改 Windows 全局代理，不影响 Claude 的代理配置。本项不代表所有媒体 CDN 或其他网络问题都已验证。


## 自动收尾与任务记录

“结束对话”或窗口“进入待机”会立刻停止接收新任务和新附件，已接收的队列与下载继续处理，完成后自动转为蓝色待机。期间可用 `/stop`、`/stopall` 取消普通任务，或说“开始对话”继续接收任务；已有提醒保持原规则。重启与彻底退出仍会拒绝中断忙碌任务。

发 `/tasks`（也可说“任务记录”“最近任务”）查看自己的最近任务，待机时也可查看。窗口最近动态下方显示本机任务记录。记录从本次升级后开始，覆盖 Claude 队列任务、文件发送、屏幕分析和附件接收；即时音量/开关应用等同步动作不在这一版记录范围内。

任务记录保存于配置 `task_journal_file` 指定的 `.runtime/tasks.sqlite`，存用户标识、消息标识、任务摘要、状态与时间。为支持手动恢复，新接收的普通文字任务会暂存交给 Claude 的完整任务正文；开始执行或取消时清空正文列。不保存微信登录令牌、回复凭据、原始消息对象或附件内容。正文可能包含用户自己的私人信息，请按本地工作数据保管数据库；清空字段不等于磁盘安全擦除。保留最近约 200 条已结束记录，待恢复和结果不确定的记录不自动删除；该数据库不允许作为附件发送。

重启后，新版保存了正文且尚未开始的普通文字任务显示“未开始，可手动恢复”。先说“开始对话”，再从 `/tasks` 复制 `/resume 任务编号`，即可重新排队；队列满时保留恢复资格，同一任务不能重复恢复，其他用户不能恢复你的任务。恢复使用当前配置、当前 Claude 会话和新消息的回复通道，不保证重现旧会话环境。已开始、等待确认及旧版没有正文的任务仍标为“结果不确定”，需要检查实际结果后重新发送。附件接收显示“已中断，请检查后重新发送”，屏幕点击、截图及文件发送不提供恢复入口。所有任务都不会自动重跑。完成状态表示处理流程结束，不等于外部应用效果已逐项核实。

托盘窗口隐藏时每 5 秒刷新，显示时每 1 秒刷新；提交控制操作时临时加快刷新。桌面、窗口和托盘统一为双对话气泡。运行中心标题、状态点和托盘图标以蓝灰色表示待机，以绿色表示已唤醒；右上角“微信已连接”独立表示连接正常，待机时也保持绿色。


## 故障说明、固定记忆与任务进度

- 主界面显示易懂的故障原因与建议：加密连接中断、DNS 解析失败、服务器无响应、登录可能失效等。已经正常通信后，短暂中断（默认 30 秒内自愈）不升级为界面故障，恢复后也不播报；持续超过 30 秒才显示故障，超过 3 分钟显示红色，仍会按后台策略重试；恢复后清除当前故障。凭据被拒等需要人工处理的情况仍立即显示。重复同类网络错误不反复刷主界面，原始错误仍保留在本机日志。
- 点击窗口右上角或托盘菜单的“固定记忆”，可查看和编辑已有记忆，选择目录后添加为桌面、常用工作目录或默认输出目录，也可直接记录偏好。清空编辑区后仍需点“保存记忆”才生效；关闭时提醒未保存内容。
- 保存会检测其他程序是否改过原文件，防止覆盖；内容上限 12000 字符，采用同目录临时文件替换。保存后下一次 Claude 调用读取新内容，当前任务不受影响。不要填写密码、令牌或密钥。它是模型参考信息，不会自动扩大文件访问权限，也不会自动修改系统目录。
- 当前配置 `task_progress: true`：普通任务先报告接收／排队，再报告开始处理；附件接收、文件上传有对应阶段提示。长任务首次到配置的 `progress_notice_seconds`（默认 30 秒）时提示当前阶段和已用时间，之后约每分钟更新，直到完成或停止。
- 窗口任务概览同步显示阶段。仅报告后台能确认的阶段，不编造进度百分比、预计完成时间或 Claude 内部正在读哪个文件。
- 固定记忆界面验证命令：`powershell -NoProfile -STA -ExecutionPolicy Bypass -File .\memory_editor.ps1 -Verify`，只操作临时测试文件，不修改真实记忆。


## 一句话查看进度

发送“现在怎么样”“现在什么情况”“还在处理吗”“处理到哪了”“进度怎么样”或 `/brief`，可简短查看当前任务、已用时间、已知阶段、排队数量、附件接收数量和最近一条任务结果记录。可以带问号，也可带 `/cc` 前缀；待机或收尾期间也能查询，不会唤醒助手，不会延长对话或启动任务。

只展示自己的任务内容和历史；其他用户的当前任务仅显示“另一个用户的任务”。最近记录只表示处理状态，不声称文件或外部应用效果已经验证。有待检查或恢复的任务时会提示 `/tasks`。查询必须是一条完整的状态问句：例如“现在怎么样，帮我打开微信”不会被截成状态查询；带图片或文件的消息继续走原来的附件规则。原 `/status` 仍显示详细状态。

## 任务结果反馈

- 发文件：微信接口接受后，追加文件名、实际上传大小和本机来源路径的文字回执。该回执不表示手机已经下载或阅读文件。网络异常显示“未获得发送成功确认”，请先检查微信附件再决定是否重发；本地文件不存在或不可读则报告失败。
- 打开应用：保留“已请求打开，尚未确认窗口是否出现”，并给出 `/see 应用名` 查看入口。不会凭已有同名窗口就宣称本次启动成功。
- 停止任务：`/stop` 和托盘先报告“已请求停止”，执行线程退出后才报告“已叫停”；停止不回滚此前的文件改动。屏幕分析任务被取消也会正确记录为取消。
- Claude 返回非零退出码或明确的错误状态时，即使带有文字也按失败处理，保留错误说明；错误输出中的发文件标记不会触发上传。
- 普通文件处理的自由文本仍由模型提供；明确声明的任务产物会核对真实文件并做有限基础检查，普通文字路径不自动登记，文件内容正确性不在核验范围内。文件回执中的大小来自本次实际上传读取的数据。

## 任务产物取回与单条队列管理

发 `/artifacts 任务编号` 或 `/artifacts latest` 查看自己的已结束任务产物清单；“查看刚才的产物”是完整句别名，待机可查。先“开始对话”，再发 `/getfile 任务编号 序号` 或 `/getfile 任务编号 all` 取回；任务编号也可写 `latest`。完整句“把刚才的产物发给我”“把刚才生成的文件发给我”对应全部取回，待机或收尾时不会入队。

只登记模型独立行 `[[产物]]` JSON 明确声明的文件，不从普通文字中的路径推断。每次最多核验 20 项、每个 100 MB；未知格式只做基础读取，DOCX/XLSX/PPTX 检查包结构，PDF 和图片检查基础文件头等有限结构，不证明内容正确或文件由本任务创建。取回仍受默认每次 3 个、单个 20 MB 的发送上限限制，`all` 超过数量上限时先要求按序号取回；文件改变或消失拒发，核对指纹后发送同版本快照。

先发 `/queue` 复制完整编号；`/queue cancel 编号` 单条取消，`/queue edit 编号 新正文` 修改普通文字任务，`/queue move 编号 N` 调到本人等待任务的第 N 条。只操作自己的未开始任务；附件和电脑操作只能取消或调序，收尾期间仍可管理。修改正文仍交给原模型任务通道，不即时执行正文中的管理动作。调序仅本次运行有效，重启后未开始普通文字任务需手动恢复；关闭任务记录后仍可管理内存队列，但没有持久化恢复，也不能按任务取产物。详见 [功能改进：产物与队列](../features/功能改进-产物与队列.md)。

## 多附件组成一个批次

先“开始对话”，发 `/batch new 名称` 收集随后附件；附件仅保存，附带正文不自动分析。已保存材料可用 `/batch recent N 名称`：接指令时固定本人最新 N 个登记项，从新到旧在附件后台队列核对准备；不跳过丢失项换旧件，也不收后续附件，准备中不能确认清单。用 `/batch list` 查编号、`/batch show 完整编号` 核对序号；`/batch template 编号 N` 标记单个模板，N 为 0 时清除；`/batch seal 编号` 确认清单固定后，用 `/batch run 编号 任务说明` 绑定一条任务并执行。`/batch cancel 编号` 只取消未使用的批次。

查询待机可用，收集、修改批次和执行需先开始对话。每人最多一个正在收集的批次，每批 1 至 12 个文件、单个 20 MB、总量 100 MB；模板在确认清单前标记，确认后不能改。有待下载或下载失败时不能确认，新收件批次失败可补传缺失文件，核对后移除失败记录；`recent` 准备失败仍需取消重建。执行前复核所有文件指纹并创建输入副本，任一文件变化即拒绝整批，后收到的附件不混入。同一批次只能绑定一次任务；异常重启后 `/resume` 手动恢复未开始任务，保留原清单。批次依赖启用的任务记录库。详情见 [功能改进：附件批次](../features/功能改进-附件批次.md)，现有运行中心布局保持不变。

单条取消批次任务不会让原批次重新可运行，需要另建批次；执行中失败或停止先核对结果再重建。桌面任务历史沿用详情区显示固定输入清单，查看不会自动执行或恢复。

## 常用任务模板

先“开始对话”，用 `/template save 名称` 保存常用任务，后面分别以 `输入：`、`步骤：`、`输出目录：`、`输出格式：` 单独起一行填写要求，字段内容可以续行。可在最后追加 `检查条件：`，逐行配置必需列、列合计或必需章节；无效规则拒绝保存，不填写时保留原四字段行为。名称为 1 至 40 个字，不能含空格；每人最多保存 30 个模板。同名保存会覆盖并递增版本，保存本身不执行任务。

`/template`、`/template help`、`/template list` 和 `/template show 名称` 可在待机查询；`/template delete 名称` 删除保存的模板。`/template run 名称 [本次补充要求]` 不自动附加最近附件；处理收到的附件时，先用 `/batch show 完整编号` 核对并 `/batch seal 完整编号` 确认，再发 `/template batch 名称 完整批次编号 [本次补充要求]`。保存、删除和运行需先开始对话，待机或收尾时不执行，指令与附件分开发送。

完整句“按周报模板运行”对应运行名为“周报”的模板，可以在后面补充本次要求。“按周报模板处理这份表”或“按周报模板处理这批附件”仅在本人恰好有一个已确认、未使用批次时绑定；没有或有多个时需先确认批次，或改用带完整编号的指令。这里的常用任务模板是保存的四项要求，与 `/batch template` 标记的格式模板文件不同。

每次入队保存模板版本、四项定义及可选检查条件，之后修改或删除模板不会改变已排队任务，异常重启后的 `/resume` 也保留原版本、检查条件与绑定清单。模板任务只可用 `/queue cancel` 取消或 `/queue move` 调序，不能 `/queue edit` 改正文。输出目录在入队时按当前工作目录解析并固定，执行前再次核对；可以写“工作目录”“工作目录/子目录”、相对路径或工作目录内的绝对路径。不会切换工作目录，越出当前工作目录或路径不合法时拒绝模型调用。任务记录的“输入与模板”页签显示模板名、版本和四项要求，“检查结果”页签显示已配置的检查条件和结论。

可选结果检查仅核对明确声明产物中的指定列、十进制合计或标题，不做语义审核。完成回执及 `/artifacts` 将基础检查与结果检查分开；不通过或未能检查仍保留产物供取回，不自动重跑、不改写生成任务的执行终态。`/result` 与 `/resend` 保留原检查结论。规则、格式和限额见 [功能改进：任务模板](../features/功能改进-任务模板.md)。模板与检查条件的当前验证及加载记录见 [可靠性检查与验收](../testing/可靠性检查与验收.md)，手机操作仍待实测。

## 取消、附件结果与历史读取

- 任务刚出队、正在保存执行状态时也可以停止。`/stop` 只停止当前任务；`/stopall` 还取消当时队列中的任务，之后新接收的任务照常处理。停止请求不撤销已经发生的文件修改或附件发布。
- 请求的附件超过 `send_file.max_per_reply` 时，只尝试上限以内的文件，并列出因上限未发送的文件；本次任务记为未全部完成，不转发模型的“全部发送完成”说明。存在未确认的传输时继续标为结果不确定，先检查手机附件再决定是否重发。
- Claude、DeepSeek 和自定义 Claude 后端统一读取最终结果中的权限拒绝。存在未获许可的操作时报告未全部完成，不上传失败结果中的附件标记；模型有响应与本机操作全部完成分别判断。
- 历史库暂时不可读或被锁住时，运行中心继续刷新连接、当前任务和心跳。历史区域明确提示无法读取；如保留上次记录，会注明尚未刷新。
- 任务历史窗口优先读取正在运行的后台实际加载的数据库；后台停止后按 `task_journal_file` 读取。后台状态陈旧、旧版缺少来源信息、配置错误、库不存在和关闭记录都有明确提示，不会悄悄切到默认旧库。查看历史始终只读，不触发任务恢复。

## 结果查看、文字补发与人工结清（2026-10-02）

- `/result 任务编号`：查看保存的完整结果文字；不重新运行任务。编号可从 `/tasks` 或桌面任务记录获取。
- `/resend 任务编号`：只补发任务库中未保存微信接口确认的文字部分，跳过已记录确认的段落。最后一次未确认的段落可能重复；若回执写盘失败，其他已收到却未留记录的段落也可能重复，先检查手机。补发不重新执行任务，也不重新上传附件。
- `/resolve 任务编号 checked`：检查实际结果后标记“已人工核对”；适用于结果不确定或附件中断的记录。
- `/resolve 任务编号 abandoned`：放弃恢复未开始的任务；`archived` 则归档已结束或未开始的记录。原始状态与人工确认时间保留，已结清记录不再触发恢复提醒；执行中或等待确认的任务不能结清。
- 上述操作仅允许任务本人使用，待机时也可用。桌面历史窗口支持复制微信指令，新版后台还支持直接恢复、取消排队和人工结清；操作按钮按后台实际支持的能力启用。
- 执行状态和文字发送状态分别显示。接口接受仍不代表手机已阅读；补发成功也不自动消除实际操作结果的不确定性。
- 完整结果文字在任务库内保留 7 天供查看和补发，启动或写入时清理过期缓存；可能含私人内容，不保存回复令牌或附件二进制。过期清理不等于磁盘安全擦除，旧任务不补造全文。

网络通知在释放桌面控制锁后发送，慢通知不会挡住桌面停止请求。微信停止和状态指令不依赖历史提醒查询；`/tasks` 与 `/brief` 遇到历史读取故障会明确降级。启用任务记录时，普通业务消息先保存分发记录再执行；记录写入失败时保留旧游标并有界重试，已有执行痕迹的失败消息不会自动重跑。关闭任务记录后不具备跨重启的分发保护。
