# 发布新版本与自动更新

微信助手通过 GitHub Releases 发布新版本。安装后的程序会定期检查，发现新版本时提示用户，并可一键下载、校验、安装后自动重新打开。

## 前提

- 仓库需要**公开**，并至少发布过一个 Release。私有仓库或尚未发布时，检查结果显示“没有找到已发布的版本”。
- 版本号写在根目录 `VERSION`（如 `1.2.0`），发布标签为 `v` 加同一版本号（`v1.2.0`）。预发布可写成 `1.3.0-beta.1`。

## 发布步骤（维护者）

1. 修改 `VERSION`，提交并推送到 `main`。
2. 打标签并推送：

   ```powershell
   git tag v1.2.0
   git push origin v1.2.0
   ```

3. GitHub Actions 的 Release 工作流会核对 `VERSION` 与标签一致，用 `git archive` 打包 `WECHAT-BOT-1.2.0.zip`，生成 `SHA256SUMS.txt`，并创建 Release（自动生成更新说明）。已手动创建的同名 Release 只会补传这两个文件。
4. 在 Release 页面按需编辑更新说明。用户在“版本更新”窗口中看到的就是这段内容（Markdown 标题和列表会简化显示）。

没有附件的 Release 也能更新：程序会改用 GitHub 自动生成的源码压缩包，但没有 SHA-256 可供校验，安装前会提示用户。

## 用户看到什么

- 运行中心启动约 20 秒后检查一次，之后每 6 小时检查一次；网络失败时 30 分钟后重试。
- 有新版本时，运行中心标题栏右侧出现“新版本 vX.Y.Z”按钮，托盘弹出一次通知，托盘菜单顶部出现“更新到 vX.Y.Z…”。“设置 → 检查更新”可随时手动检查。
- “版本更新”窗口显示版本、发布日期和更新说明，可“立即更新”“稍后”或“跳过此版本”（跳过后，只有更新的版本才会再提醒）。
- 微信发送 `/version` 可查看当前版本和最近一次检查结果。

## 一键更新做了什么

1. 有任务、排队或附件处理时不允许开始。
2. 只通过 HTTPS 从 GitHub 域名下载，跳转到其他域名会被拒绝；安装包有 SHA-256（Release 附件摘要或 `SHA256SUMS.txt`）时必须一致。
3. 解压时拒绝绝对路径、`..` 和链接文件，并限制文件数量与大小；新版本必须包含核心程序文件，且 `VERSION` 与标签一致。
4. 确认后，运行中心启动安装程序并退出；安装程序等待运行中心和后台都退出，再替换程序文件，最后自动重新打开助手。
5. 被替换的文件先备份到 `.runtime/update/backup/`；任何一步出错都会恢复原文件，并在重新打开后说明原因。`requirements.txt` 有变化时会自动安装依赖。

**不会改动的内容**：`config.json`、`BOT_MEMORY.md`、`.runtime/` 下的任务库与密钥、会话索引、日志及其他本机数据。只删除上一次更新安装过、而新版本已不再包含的程序文件。

Git 克隆的开发目录只提示新版本，不会自动覆盖，请使用 `git pull`。

## 配置

`config.json` 中的 `update` 段（缺省即为下列值）：

```json
"update": {
  "enabled": true,
  "repo": "query11/WECHAT-BOT",
  "prerelease": false
}
```

- `enabled: false` 关闭检查与提示。
- `repo` 改为发布新版本的仓库（`拥有者/仓库名`）。
- `prerelease: true` 时也提示预发布版本。

检查状态保存在 `.runtime/update.json`，用户选择保存在 `.runtime/update-prefs.json`，安装记录在 `.runtime/update/`。也可以在项目目录手动执行：

```powershell
python updater.py check --force
```
