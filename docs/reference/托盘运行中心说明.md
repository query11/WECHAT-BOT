# 微信助手 · 托盘运行中心

> 本文保留详细行为说明及历史维护记录；首次安装请先阅读[快速开始](../QUICKSTART.md)。本机路径已改为示例，历史验证结论只代表当时环境。

> 本文描述当前用法。最新验证范围见 [可靠性检查与验收](../testing/可靠性检查与验收.md)，旧版行为和测试记录见 [验收历史记录](../archive/验收历史记录.md)。

当前任务卡片支持真实阶段、总耗时及阶段耗时，阶段提示中可查看实际经过的流程；没有进度数据时不推算百分比。运行中心、任务记录、任务模板、快捷任务分别记住窗口尺寸及适用的列宽、状态筛选和页签。详见 [阶段进度与界面记忆](../features/功能改进-阶段进度与界面记忆.md)。

> 当前使用规则（2026-09-29）：发「开始对话」一步唤醒并进入对话；发「结束对话」一步退出并待机。原来的「启动助手／停止助手」仍可用。任务或附件尚未完成时停止接收新任务，已有任务收尾后自动待机，无需再说一次。下文前缀模式的用法仅在助手已唤醒时适用；关闭 `standby_on_start` 才恢复旧版独立对话开关行为。
>
> 桌面固定记忆：`C:\Users\your-name\Desktop`，已由 Windows 系统配置核对。`BOT_MEMORY.md` 经 `bot_memory_file` 配置在每次 Claude 调用时注入；`/new`、上下文过期或重启不会清掉它。修改该文件后下一次调用即生效。

双击项目中的 `微信助手.bat` 打开运行中心。重复打开只显示已有窗口，不重复启动后台。

登录 Windows 后自动启动后台和托盘，默认在线待机。双击托盘图标显示窗口，关闭窗口仍保留托盘；右键托盘选择“退出程序”才会请求停止后台并退出。

| 颜色 / 图形 | 状态 |
| --- | --- |
| 蓝灰色气泡 | 微信通信正常，在线待机 |
| 绿色气泡 | 微信通信正常，助手已唤醒，可接收任务 |
| 黄色气泡 / 感叹号 | 连接中、重连中或通信长时间未成功 |
| 红色气泡 / 叉号 | 连接被拒、任务线程停止、后台异常退出或状态更新中断 |
| 灰色气泡 / 横线 | 后台已停止 |

绿色不代表正在执行某条任务，请看窗口中的“当前任务”。运行中心的待机标题为蓝灰色，已唤醒标题为绿色；右上角“微信已连接”在这两种状态下都保持绿色，只表示连接正常。单个任务失败记录在最近运行记录中，不会直接将整个服务判为故障。首次成功通信之前不会显示蓝灰色或绿色。

## 结果查看、文字补发与人工结清（2026-10-02）

- `/result 任务编号`：查看保存的完整结果文字；不重新运行任务。编号可从 `/tasks` 或桌面任务记录获取。
- `/resend 任务编号`：只补发任务库中未保存微信接口确认的文字部分，跳过已记录确认的段落。最后一次未确认的段落可能重复；若回执写盘失败，其他已收到却未留记录的段落也可能重复，先检查手机。补发不重新执行任务，也不重新上传附件。
- `/resolve 任务编号 checked`：检查实际结果后标记“已人工核对”；适用于结果不确定或附件中断的记录。
- `/resolve 任务编号 abandoned`：放弃恢复未开始的任务；`archived` 则归档已结束或未开始的记录。原始状态与人工确认时间保留，已结清记录不再触发恢复提醒；执行中或等待确认的任务不能结清。
- 上述操作仅允许任务本人使用，待机时也可用。桌面历史窗口支持复制微信指令，新版后台还支持直接恢复、取消排队和人工结清；操作按钮按后台实际支持的能力启用。
- 执行状态和文字发送状态分别显示。接口接受仍不代表手机已阅读；补发成功也不自动消除实际操作结果的不确定性。
- 完整结果文字在任务库内保留 7 天供查看和补发，启动或写入时清理过期缓存；可能含私人内容，不保存回复令牌或附件二进制。过期清理不等于磁盘安全擦除，旧任务不补造全文。

网络通知在释放桌面控制锁后发送，慢通知不会挡住桌面停止请求。微信停止和状态指令不依赖历史提醒查询；`/tasks` 与 `/brief` 遇到历史读取故障会明确降级。启用任务记录时，普通业务消息先保存分发记录再执行；记录写入失败时保留旧游标并有界重试，已有执行痕迹的失败消息不会自动重跑。关闭任务记录后不具备跨重启的分发保护。

## 产物取回与排队管理

本轮保持运行中心布局，新增操作从微信使用。发 `/artifacts 任务编号` 或 `/artifacts latest` 查看自己的已结束任务产物清单，完整句“查看刚才的产物”也可，待机时能查。先“开始对话”后发 `/getfile 任务编号 序号|all` 取回文件，编号也可写 `latest`；完整句“把刚才的产物发给我”“把刚才生成的文件发给我”对应全部取回。文件取回作为新的附件发送任务排队，待机或收尾期间不会入队；查看清单不重新执行原任务。

清单只登记模型明确声明的文件并做有限基础检查，不猜普通文字路径，不证明内容正确或由本任务创建。每次最多核验 20 个声明、每个 100 MB；未知格式只做基础读取，DOCX/XLSX/PPTX 检查包结构，PDF 和图片检查基础文件头等有限结构。取回仍按默认每次 3 个、单个 20 MB 的发送上限；`all` 超过数量上限时先要求按序号取回。文件变更或消失会拒发，核对指纹后上传同版本快照。

`/queue` 显示自己的完整编号和“你的第 N 条”。用 `/queue cancel 编号` 取消、`/queue edit 编号 新正文` 修改普通文字正文、`/queue move 编号 N` 调整本人等待顺序；只操作本人尚未开始的任务，附件和电脑操作只能取消或调序，收尾期间仍可管理。修改正文仍走原模型任务通道，不会即时执行关机等管理动作。调序仅本次运行有效，重启未开始普通文字任务仍需手动恢复；记录库关闭时队列操作可用，但没有持久化恢复，也不能按任务取回产物。详情见 [功能改进：产物与队列](../features/功能改进-产物与队列.md)。

## 附件批次

批次功能从微信使用，运行中心继续显示原来的任务、队列和附件接收状态，不改变现有布局。先“开始对话”，发 `/batch new 名称` 后发送材料，只接收保存，附件消息正文不自动分析；或用 `/batch recent N 名称` 固定本人最新 N 个收件登记项，按新到旧在附件后台队列准备清单，不跳过丢失项换旧件，不接入后来收到的附件，准备中不能确认清单。

`/batch help`、`/batch list` 和 `/batch show 完整编号` 可在待机查询。确认文件序号后，用 `/batch template 编号 N` 标记一个模板（0 清除）、`/batch seal 编号` 固定清单，再 `/batch run 编号 任务说明` 绑定一次任务；收集和执行都需先开始对话。`/batch cancel 编号` 只取消未使用的批次，已保存原附件不删除。

批次依赖启用的任务记录库，每人最多一个正在收集的批次；每批 1 至 12 个文件、单个 20 MB、总量 100 MB。模板在确认前标记，确认后不能修改；确认、标模板和取消也需先开始对话。待下载先等待，下载失败不能确认清单；新收件批次可补传缺失文件、核对后移除失败记录；`recent` 准备失败仍需取消重建。执行前复核所有文件指纹并创建副本，任一文件变化即拒绝整批，后收附件不混入；异常重启后的 `/resume` 保留原清单，沿用未开始任务手动恢复规则。输入版本固定不等于业务内容或模型结果已经核实。完整说明见 [功能改进：附件批次](../features/功能改进-附件批次.md)。

单条取消批次任务不会让原批次重新可运行，后续处理需另建批次；执行中失败或停止先核对结果再重建。桌面任务记录的“输入与模板”页签显示固定输入清单，查看不触发执行或自动恢复。

## 常用任务模板

运行中心还提供“运行模板”和“附件核对”：每位用户可固定 5 个常用模板，选择明确输入或已确认附件批次，核对后确认运行。模板执行仍需对应微信用户唤醒并有回复通道。空闲时“最近结果”卡片展示摘要、检查结论和文件操作；用法见 [常用模板、附件核对与结果卡片](../features/功能改进-快捷模板与附件核对.md)。

模板可从微信或电脑管理。点击运行中心“常用入口”右上角或托盘菜单的“任务模板”，即可新建、修改、复制和删除；在线待机也可编辑。任务记录中的“保存为模板”会生成草稿供检查，普通任务需补齐要求。详情页先展示摘要和文件，再按页签查看完整回复、输入与模板、检查结果；按钮显示具体动作及不可用原因。用法见 [模板窗口与任务详情](../features/功能改进-模板窗口与任务详情.md)，验证与加载情况见 [可靠性检查与验收](../testing/可靠性检查与验收.md)。

先“开始对话”，用 `/template save 名称`，后接分别以 `输入：`、`步骤：`、`输出目录：`、`输出格式：` 单独起行的四项要求保存模板，内容可以续行。名称为 1 至 40 个字，不能含空格；每人最多保存 30 个模板，同名保存会覆盖并递增版本。保存仅记录文本，不执行任务。

`/template`、`/template help`、`/template list`、`/template show 名称` 可在待机查看；`/template delete 名称` 删除保存的模板。用 `/template run 名称 [本次补充要求]` 运行模板明确指定的输入，不自动附加最近附件；处理收到的附件时先核对并确认批次，再用 `/template batch 名称 完整批次编号 [本次补充要求]`。保存、删除和运行需先开始对话，待机或收尾时不执行，模板指令与附件分开发送。

完整句“按周报模板运行”可直接运行名为“周报”的模板并附加本次要求；“按周报模板处理这份表”或“按周报模板处理这批附件”仅在本人恰好有一个已确认、未使用批次时绑定，否则需先确认或用完整编号指定。常用任务模板保存的是四项要求，与 `/batch template` 标记的格式模板文件不同。

入队时保存模板版本和定义，之后修改或删除模板不影响已排队任务，异常重启后的 `/resume` 仍保留原版本与绑定清单。模板任务只可用 `/queue cancel` 取消或 `/queue move` 调序，不能 `/queue edit` 改正文。输出目录按执行时的当前工作目录解析，可写“工作目录”“工作目录/子目录”、相对路径或其内绝对路径；不切换工作目录，越界或非法目录时拒绝模型调用。任务历史在原详情区追加模板名、版本和四项要求；查看不执行任务或恢复操作。完整示例见 [功能改进：任务模板](../features/功能改进-任务模板.md)。

## 窗口功能

- 显示运行时长、最近成功通信时间、当前任务、队列和附件处理数量。
- “助手状态”卡的主按钮按当前状态显示“唤醒助手”“进入待机”或“继续接收任务”；服务停止时显示“启动服务”。唤醒和待机作用于本机所有已配置的白名单用户，不发送微信消息。
- “停止当前任务”复用现有取消逻辑；文件可能已被部分修改，不等于回滚。
- “重启服务”和“退出程序”在任务或附件未完成时拒绝执行；先等待或停止当前任务。正常停止可能要等待一轮长轮询结束。
- 右侧“服务维护”提供“重启服务”和“打开日志”；有任务、队列或附件处理时暂不能重启。日志包含本地完整记录，注意不要把含个人信息的日志随意转发。
- 待机仍会通知已设置的提醒；息屏不影响运行，睡眠、休眠和关机会暂停服务。

原 `微信开关.bat` 仍是彻底启停后台的兼容入口，日常优先用托盘。完全退出后微信无法唤醒，需重新打开助手或下次登录 Windows。

### 版本提示与更新后重启

“服务维护”显示“代码已更新，重启后生效”时，表示已加载的后台源码在磁盘上发生了变化。先等当前任务、队列和附件处理完成，再点“重启服务”。后台约每 60 秒检查一次；文档修改或仅提交号变化不会触发提示，也不会自动重启。

悬停在该说明文字或“重启服务”按钮上，可查看版本诊断和启动时提交号。“版本状态未知”表示缺少足够证据，例如启动后延迟加载的模块无法确认加载时版本，或源码暂时无法读取；它不代表已是最新版，也不表示微信连接失败。缺少加载证据的模块会持续保持未知，已确认的其他源码变化仍优先显示重启提示。重启会加载当前磁盘代码并建立新的启动基线，之后再次延迟加载模块仍可能变为未知。连接与任务状态请分别看原来的状态卡。

“重启服务”只重启后台；托盘脚本更新后，要等任务收尾，用菜单“退出程序”，再双击 `微信助手.bat` 重新打开。关闭窗口只会隐藏，不能加载新版托盘。`toggle.ps1 -Off` 会强制终止后台进程树，日常更新请使用运行中心的正常重启或退出。

## 实现与验收

使用 Windows 自带 WinForms 和 NotifyIcon，无需安装额外 Python 包。后台通过项目 `.runtime` 目录提供本机状态与固定操作请求，不开放 HTTP 服务，不在状态中输出登录凭据。自启动仍使用当前用户 Startup 快捷方式，目标已更新为 `launch_tray.ps1`。

2026-09-30 启动生命周期修复：隐藏命令行窗口不等于进程独立。此前从 Codex 启动的后台和托盘继承了宿主的 Windows Job Object，宿主退出或被结束时会一并清理它们。现在 `launch_tray.ps1`、`toggle.ps1` 和直接运行的托盘入口共用独立启动器；遇到退出时清理子进程的宿主，通过现有桌面 Explorer 代理启动，并在允许时脱离进程组。本机 Explorer 所在的 Windows 共享进程组不含这项退出清理规则，属于正常情况。交接文件只暂存路径、参数和编码／调试标记，完成后删除；不复制密钥或完整环境，不修改自启动快捷方式、系统代理或用户配置。

关闭 Codex 后，助手应继续运行；关闭运行中心窗口仍隐藏到托盘，托盘“退出程序”仍停止助手。当前生命周期验证入口是 `python tools/verify.py --suite integration`，须显式指定；它使用临时宿主与心跳子进程，不启动真实后台。2026-09-30 的旧批次用临时后台心跳和 WinForms 消息循环检查了宿主进程组关闭、禁止脱离及 MTA 命令宿主；旧启动方式随宿主退出，新方式继续运行，日志保存在 `.runtime/process-isolation-tests.txt`。该批实际后台与托盘已切换到独立入口，确认均不在 Codex 的退出清理进程组中，微信通信、窗口可见和重复打开行为见 `.runtime/process-lifetime-live.json`。当时未直接结束真实 Codex，依据是模拟宿主退出测试与实际进程组成员检查。

最近一次验证的项数以 [可靠性检查与验收](../testing/可靠性检查与验收.md) 开头那条为准（代码版本不同，数量不是固定门槛）；正常重启后的微信通信和在线待机已确认。此前的界面渲染、隐藏到托盘和控制路径验证，以及仍待现场检查的 DPI、多显示器、注销登录和 Explorer 重启场景，详见 [可靠性检查与验收](../testing/可靠性检查与验收.md) 和 [验收历史记录](../archive/验收历史记录.md)。

开发离线验证：`python tools/verify.py --suite offline`；按模块排查仍可用 `python -m unittest tests.selftest_runtime tests.selftest_standby tests.selftest_reliability`。界面控制验证：`powershell -NoProfile -STA -ExecutionPolicy Bypass -File .\tray_app.ps1 -Verify`（要求后台在线待机且无任务，会短暂唤醒后恢复待机）。


界面已更新为圆角状态卡片、分级按钮和对话气泡图标。启用高 DPI 感知，并在控件构建完成后统一缩放；当前 200% 缩放预览已检查。日志仅在内容变化时刷新，不再自动整段选中。此次仅修改界面与图标，后台执行逻辑保持原样。

2026-09-30 界面优化：服务卡使用浅蓝底色与加粗状态，后端切换使用浅蓝选中样式；统一标题、间距和按钮反馈，状态与任务文字随窗口宽度伸展，最近动态支持键盘聚焦和复制。已检查 200% 缩放、加宽窗口、长故障提示和禁用后端按钮的渲染。

`powershell -NoProfile -STA -ExecutionPolicy Bypass -File .\tray_app.ps1 -Preview` 现在仅使用示例数据生成 `.runtime/tray-preview.png`，不读取真实后台状态、不消费窗口显示请求、不发送控制命令。该预览用于视觉检查，不代表真实连接或任务验证；跨屏 DPI 变化仍需现场检查。


## 自动收尾与任务记录

“结束对话”或窗口“进入待机”会立刻停止接收新任务和新附件，已接收的队列与下载继续处理，完成后自动转为蓝色待机。期间可用 `/stop`、`/stopall` 取消普通任务，或说“开始对话”继续接收任务；已有提醒保持原规则。重启与彻底退出仍会拒绝中断忙碌任务。

发 `/tasks`（也可说“任务记录”“最近任务”）查看自己的最近任务，待机时也可查看。窗口最近动态下方显示本机任务记录。记录从本次升级后开始，覆盖 Claude 队列任务、文件发送、屏幕分析和附件接收；即时音量/开关应用等同步动作不在这一版记录范围内。

任务记录保存于配置 `task_journal_file` 指定的 `.runtime/tasks.sqlite`，存用户标识、消息标识、任务摘要、状态与时间。为支持手动恢复，新接收的普通文字任务会暂存交给 Claude 的完整任务正文；开始执行或取消时清空正文列。不保存微信登录令牌、回复凭据、原始消息对象或附件内容。正文可能包含用户自己的私人信息，请按本地工作数据保管数据库；清空字段不等于磁盘安全擦除。保留最近约 200 条已结束记录，待恢复和结果不确定的记录不自动删除；该数据库不允许作为附件发送。

重启后，新版保存了正文且尚未开始的普通文字任务显示“未开始，可手动恢复”。先说“开始对话”，再从 `/tasks` 复制 `/resume 任务编号`，即可重新排队；队列满时保留恢复资格，同一任务不能重复恢复，其他用户不能恢复你的任务。恢复使用当前配置、当前 Claude 会话和新消息的回复通道，不保证重现旧会话环境。已开始、等待确认及旧版没有正文的任务仍标为“结果不确定”，需要检查实际结果后重新发送。附件接收显示“已中断，请检查后重新发送”，屏幕点击、截图及文件发送不提供恢复入口。所有任务都不会自动重跑。完成状态表示处理流程结束，不等于外部应用效果已逐项核实。

托盘窗口隐藏时每 5 秒刷新，显示时每 1 秒刷新；提交控制操作时临时加快刷新。桌面、窗口和托盘统一为双对话气泡。运行中心标题、状态点和托盘图标以蓝灰色表示待机，以绿色表示已唤醒；右上角“微信已连接”独立表示连接正常，待机时也保持绿色。


## 故障说明、固定记忆与任务进度

- 主界面显示易懂的故障原因与建议：加密连接中断、DNS 解析失败、服务器无响应、登录可能失效等。已经正常通信后，短暂中断（默认 30 秒内自愈）不升级为界面故障，恢复后也不播报；持续超过 30 秒才显示故障，超过 3 分钟显示红色，仍会按后台策略重试；恢复后清除当前故障。凭据被拒等需要人工处理的情况仍立即显示。重复同类网络错误不反复刷主界面，原始错误仍保留在本机日志。
- 代理虚拟网卡可能把微信域名解析为 `198.18.0.0/15` 或 `2001:2::/48` 内的 Fake-IP，即使系统代理开关已关闭，也可能导致加密连接中断。助手在本机解析不可信时改用加密 DNS 获取公网地址：既包括解析到上述虚拟地址，也包括系统或代理 DNS 直接解析失败（`getaddrinfo` 报错）。加密 DNS 结果按 DNS TTL 缓存，解析失败期间直接复用未过期的缓存；某个地址无法完成握手时，会在发送请求前尝试其他地址。仍使用微信域名设置 SNI、Host 和验证证书；不修改系统代理、DNS 或登录配置，自定义接口保持原连接方式。
- “微信连接已恢复正常”仅在后台存活、真实通信成功且状态已恢复后显示。重启时暂时没有错误不算连接成功；再次断线会撤下旧的恢复提示。
- 点击右侧“常用入口”或托盘菜单的“固定记忆”，可查看和编辑已有记忆，选择目录后添加为桌面、常用工作目录或默认输出目录，也可直接记录偏好。清空编辑区后仍需点“保存记忆”才生效；关闭时提醒未保存内容。
- 保存会检测其他程序是否改过原文件，防止覆盖；内容上限 12000 字符，采用同目录临时文件替换。保存后下一次 Claude 调用读取新内容，当前任务不受影响。不要填写密码、令牌或密钥。它是模型参考信息，不会自动扩大文件访问权限，也不会自动修改系统目录。
- 当前配置 `task_progress: true`：普通任务先报告接收／排队，再报告开始处理；附件接收、文件上传有对应阶段提示。长任务首次到配置的 `progress_notice_seconds`（默认 30 秒）时提示当前阶段和已用时间，之后约每分钟更新，直到完成或停止。
- 窗口任务概览同步显示阶段。仅报告后台能确认的阶段，不编造进度百分比、预计完成时间或 Claude 内部正在读哪个文件。
- 固定记忆界面验证命令：`powershell -NoProfile -STA -ExecutionPolicy Bypass -File .\memory_editor.ps1 -Verify`，只操作临时测试文件，不修改真实记忆。

## 任务结果反馈

- 发文件：微信接口接受后，追加文件名、实际上传大小和本机来源路径的文字回执。该回执不表示手机已经下载或阅读文件。网络异常显示“未获得发送成功确认”，请先检查微信附件再决定是否重发；本地文件不存在或不可读则报告失败。
- 打开应用：保留“已请求打开，尚未确认窗口是否出现”，并给出 `/see 应用名` 查看入口。不会凭已有同名窗口就宣称本次启动成功。
- 停止任务：`/stop` 和托盘先报告“已请求停止”，执行线程退出后才报告“已叫停”；停止不回滚此前的文件改动。屏幕分析任务被取消也会正确记录为取消。
- Claude 返回非零退出码或明确的错误状态时，即使带有文字也按失败处理，保留错误说明；错误输出中的发文件标记不会触发上传。
- 普通文件处理的自由文本仍由模型提供；明确声明的任务产物会核对真实文件并做有限基础检查，普通文字路径不自动登记，文件内容正确性不在核验范围内。文件回执中的大小来自本次实际上传读取的数据。

## 一句话查看进度

发送“现在怎么样”“现在什么情况”“还在处理吗”“处理到哪了”“进度怎么样”或 `/brief`，可简短查看当前任务、已用时间、已知阶段、排队数量、附件接收数量和最近一条任务结果记录。可以带问号，也可带 `/cc` 前缀；待机或收尾期间也能查询，不会唤醒助手，不会延长对话或启动任务。

只展示自己的任务内容和历史；其他用户的当前任务仅显示“另一个用户的任务”。最近记录只表示处理状态，不声称文件或外部应用效果已经验证。有待检查或恢复的任务时会提示 `/tasks`。查询必须是一条完整的状态问句：例如“现在怎么样，帮我打开微信”不会被截成状态查询；带图片或文件的消息继续走原来的附件规则。原 `/status` 仍显示详细状态。

## 模型后端开关

右侧“模型与配置”提供“DeepSeek”和“Claude”两个按钮，蓝色为当前实际后端；托盘右键菜单同步显示选中项。空闲时切换即生效并持久保存，不重启后台；任务、附件处理或收尾时不能切换。两套会话独立保留，失败会保留原后端并在操作反馈行说明。
