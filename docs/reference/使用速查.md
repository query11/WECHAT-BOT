# 使用速查：在微信上使唤本机的 Claude

> 本文保留详细行为说明及历史维护记录；首次安装请先阅读[快速开始](../QUICKSTART.md)。本机路径已改为示例，历史验证结论只代表当时环境。

> 本文描述当前用法。最新验证范围见 [可靠性检查与验收](../testing/可靠性检查与验收.md)，旧版行为和测试记录见 [验收历史记录](../archive/验收历史记录.md)。

> 当前使用规则（2026-09-29）：发「开始对话」一步唤醒并进入对话；发「结束对话」一步退出并待机。原来的「启动助手／停止助手」仍可用。任务或附件尚未完成时停止接收新任务，已有任务收尾后自动待机，无需再说一次。下文前缀模式的用法仅在助手已唤醒时适用；关闭 `standby_on_start` 才恢复旧版独立对话开关行为。
>
> 桌面固定记忆：`C:\Users\your-name\Desktop`，已由 Windows 系统配置核对。`BOT_MEMORY.md` 经 `bot_memory_file` 配置在每次 Claude 调用时注入；`/new`、上下文过期或重启不会清掉它。修改该文件后下一次调用即生效。

## 后台待机与登录自启动（2026-09-29）

任务处理中可在运行中心查看实际阶段及耗时，悬停查看经过的阶段。四个常用窗口会恢复尺寸及适用的列宽、筛选和页签；用法见 [阶段进度与界面记忆](../features/功能改进-阶段进度与界面记忆.md)。

快捷任务：运行中心“运行模板”可固定常用模板并预览后确认运行；“附件核对”管理未确认的收件清单；任务完成后在“最近结果”直接打开文件。模板执行仍需先在微信说“开始对话”。详见 [常用模板、附件核对与结果卡片](../features/功能改进-快捷模板与附件核对.md)。

桌面新增“任务模板”入口：运行中心“常用入口”或托盘菜单“设置”打开，填写要求后保存，下次在微信按模板运行。任务记录支持“保存为模板”，并将完整回复、输入与模板、检查结果分成页签；普通任务生成的模板草稿需补齐要求。详见 [模板窗口与任务详情](../features/功能改进-模板窗口与任务详情.md)。

新增快捷流程：“开始收集附件” → 发送附件 → “发完了，任务要求” → 核对清单后“确认执行这批附件”。未确认批次支持补传缺失文件后移除失败记录；桌面任务记录新增搜索、筛选及直接操作。详见 [附件对话与桌面任务操作](../features/功能改进-任务操作简化.md)，需后台加载新版后使用。

当前配置已开启 `standby_on_start`：每次桥启动都先待机，不调用 Claude，不执行普通消息或下载附件。

1. 微信直接发「开始对话」，自动唤醒并进入对话；也认「开启会话」「进入聊天模式」、`/on`、`/chat` 和原来的「启动助手」。
2. 忙完发「结束对话」，同时退出对话并回到待机（「停止助手」「助手待机」、`/off`、`/end`、`/standby` 也认）。若仍有任务或附件在处理，会立即挡住新任务，已有任务收尾后自动待机，不必再发一次。
3. `/status`、`/tasks` 和“现在怎么样”随时可查；待机时新任务和附件不会执行，也不会留待唤醒后补做。
4. 已设置的提醒仍会通知；会议确认需先唤醒助手。进入待机会清除当前待确认的点击、会议和收件清理问话。
5. 唤醒后进入现有对话模式，空闲超时仅退出免前缀对话；要回到后台待机请说「结束对话」。

执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\desktop\install_autostart.ps1` 安装当前用户登录自启动。它在 Windows 登录后隐藏运行，不是登录前的系统服务；机器息屏仍可用，睡眠和关机不可用。

`toggle.ps1 -On` 只启动或保持运行，不会关掉已有进程。双击原来的 `微信开关.bat` 仍是完全启停：完全关闭后微信不能唤醒，需本机再开启或下次登录自启动。

移除自启动：`powershell -NoProfile -ExecutionPolicy Bypass -File .\desktop\install_autostart.ps1 -Remove`。这不会停止当前进程。修改 `standby_on_start` 后须重启生效。此模式没有修改 Windows 的息屏或睡眠设置。


## 结果查看、文字补发与人工结清（2026-10-02）

- `/result 任务编号`：查看保存的完整结果文字；不重新运行任务。编号可从 `/tasks` 或桌面任务记录获取。
- `/resend 任务编号`：只补发任务库中未保存微信接口确认的文字部分，跳过已记录确认的段落。最后一次未确认的段落可能重复；若回执写盘失败，其他已收到却未留记录的段落也可能重复，先检查手机。补发不重新执行任务，也不重新上传附件。
- `/resolve 任务编号 checked`：检查实际结果后标记“已人工核对”；适用于结果不确定或附件中断的记录。
- `/resolve 任务编号 abandoned`：放弃恢复未开始的任务；`archived` 则归档已结束或未开始的记录。原始状态与人工确认时间保留，已结清记录不再触发恢复提醒；执行中或等待确认的任务不能结清。
- 上述操作仅允许任务本人使用，待机时也可用。桌面历史窗口支持复制微信指令，新版后台还支持直接恢复、取消排队和人工结清；操作按钮按后台实际支持的能力启用。
- 执行状态和文字发送状态分别显示。接口接受仍不代表手机已阅读；补发成功也不自动消除实际操作结果的不确定性。
- 完整结果文字在任务库内保留 7 天供查看和补发，启动或写入时清理过期缓存；可能含私人内容，不保存回复令牌或附件二进制。过期清理不等于磁盘安全擦除，旧任务不补造全文。

网络通知在释放桌面控制锁后发送，慢通知不会挡住桌面停止请求。微信停止和状态指令不依赖历史提醒查询；`/tasks` 与 `/brief` 遇到历史读取故障会明确降级。启用任务记录时，普通业务消息先保存分发记录再执行；记录写入失败时保留旧游标并有界重试，已有执行痕迹的失败消息不会自动重跑。关闭任务记录后不具备跨重启的分发保护。

## 任务产物与单条队列管理（2026-10-03）

任务完成后，模型明确声明的交付文件会形成产物清单，记录存在、非空、可读取及有限的格式检查结果。它不证明文件内容正确或由本任务创建，也不会从普通文字路径猜产物。

| 指令 | 用途 |
| --- | --- |
| `/artifacts 编号` 或 `/artifacts latest` | 查看指定任务或自己最近已结束任务的产物清单；待机可查 |
| `/getfile 编号 1` 或 `/getfile 编号 all` | 按清单序号取回一个或全部文件；编号也可写 `latest`，需先开始对话 |
| `/queue cancel 完整编号` | 取消自己尚未开始的一条任务 |
| `/queue edit 完整编号 新正文` | 修改自己尚未开始的普通文字任务正文 |
| `/queue move 完整编号 N` | 调到本人排队任务中的第 N 条，不改变其他用户占据的位置 |

完整句“查看刚才的产物”“把刚才的产物发给我”“把刚才生成的文件发给我”分别对应清单查询与全部取回。以上指令不用带 `/cc`；文件取回在待机或收尾时不会入队，单条队列管理在收尾时仍可用。清单查询、取回只允许任务本人使用，未开始或执行中的任务暂不能取产物。

每次最多核验 20 个声明、每个不超过 100 MB；未知格式只做基础读取，DOCX/XLSX/PPTX 检查包结构，PDF 和图片只检查基础文件头等有限结构。取回仍按默认每次 3 个、单个 20 MB 的发送上限；`all` 超过数量上限时先要求按序号取回。上传前重新核对指纹，改变或消失的文件拒发，核对通过后发送同版本快照。

先发 `/queue` 复制完整 32 位编号和本人序号。附件、点击、截图、发文件任务只能取消或调序；`edit` 只是修改等待执行的模型正文，不会即时执行正文中的关机等管理动作。调序仅本次运行有效；重启后未开始普通文字任务仍需手动恢复。关闭任务记录时队列操作仍可用，但不支持持久化恢复，产物也不能按任务取回。详见 [功能改进：产物与队列](../features/功能改进-产物与队列.md)。

## 多附件批次：发齐后再处理

先“开始对话”，发 `/batch new 本次报销`，随后发送发票、材料和模板。收集中的附件只保存，附带正文不自动分析；等收齐后再发送真正的处理说明。

| 指令 | 用途 |
| --- | --- |
| `/batch new 名称` | 收集随后附件，仅保存 |
| `/batch recent N 名称` | 固定本人最新 N 个收件登记项，后台核对后发清单 |
| `/batch help`、`/batch list`、`/batch show 完整编号` | 查看用法、自己的批次及文件序号；待机可查 |
| `/batch template 编号 N` | 标记清单中的单个模板；0 清除标记 |
| `/batch seal 编号` | 确认文件清单固定 |
| `/batch run 编号 任务说明` | 已确认清单绑定一次任务并执行 |
| `/batch cancel 编号` | 取消尚未使用的批次，已保存原附件保留 |

例如先 `show` 核对第 4 个确实是模板，再 `template 编号 4`、`seal 编号`、`run 编号 按模板整理三张发票`。所有编号完整复制，不猜“第三批”。收集、修改批次和执行需先开始对话，批次依赖启用的任务记录库。每人最多一个正在收集的批次；每批 1 至 12 个文件、单个 20 MB、总量 100 MB。模板在 `seal` 前标记，之后不能改。待下载先等接收完成，失败不能 `seal`；核对后先取消原批次，再用 `recent` 重建清单。执行前全部文件复核指纹并创建副本，任一文件变化拒绝整批，后收到的附件不混入；`/resume` 保留原清单，仍不自动重跑。详情见 [功能改进：附件批次](../features/功能改进-附件批次.md)。

`recent` 在接命令时选定 N 项，从新到旧排列，不跳过丢失项替换为旧文件；附件后台准备中不能 `seal`，后来收到的附件也不加入。单条取消批次任务后原批次不能再 `run`，需另建；执行中失败先核对结果再重建。桌面任务历史详情展示固定输入清单，仍沿用现有布局。

## 常用任务模板：固定要求，重复使用

原四字段任务模板已有本机验证及后台加载记录；本轮新增检查需后台加载后生效，本次未重启，手机操作仍待实测。当前验证范围统一见 [可靠性检查与验收](../testing/可靠性检查与验收.md)。先“开始对话”，将下面整段作为一条纯文字消息发送：

```text
/template save 周报
输入：已确认批次中的本周工作表
步骤：按项目汇总进展、问题和下周计划；保留原始事实，不补造未提供的数据
输出目录：工作目录/周报
输出格式：Markdown，包含进展、问题和下周计划三部分
```

四个字段各自单独起一行，内容可以续行；保存只记下要求，不会执行任务。名称为 1 至 40 个字，不能含空格；每人最多保存 30 个模板，同名保存会覆盖并递增版本。不配置检查条件时，原四字段行为保持不变。

需要检查结果时，在四项要求之后追加可选的第五个字段，每行写一条规则。例如任务明确要交付 `汇总.xlsx` 和 `周报.md` 时可填写：

```text
检查条件：
必需列 | 汇总.xlsx | 汇总 | 项目,金额
列合计 | 汇总.xlsx | 汇总 | 金额 | 1200.00
必需章节 | 周报.md | 进展,问题,下周计划
```

CSV 的工作表位置写 `-`；XLSX 填准确工作表名。列名取首个非空行，金额使用十进制精确合计；不执行公式，目标金额列有公式时，即使带缓存也显示未能检查。章节检查只支持 Markdown 实际标题、TXT 独立整行和 DOCX 标题样式，不评价语义。竖线可用 `|` 或 `｜`，列名、章节名用逗号分隔。

最多 12 条规则、检查条件总长 4000 字；每个被检查文件最多 10 MiB，表格最多 20000 行、200 列。保存时拒绝无效语法；运行时精确匹配声明产物的文件名，多个同名、解析失败、格式或限额不支持会写明无法检查，不冒充通过。完成回执与 `/artifacts` 分开显示基础检查和结果检查；检查不通过仍保留产物，满足原发送规则即可取回。检查不自动重跑或改写生成任务终态，`/result`、`/resend` 保留原结论。

| 指令 | 用途 |
| --- | --- |
| `/template` 或 `/template help` | 查看模板用法；待机可查 |
| `/template list` | 查看自己保存的模板；待机可查 |
| `/template show 名称` | 查看模板版本、四项要求及已配置的检查条件；待机可查 |
| `/template save 名称` 后接四个必填字段及可选检查条件 | 新建或覆盖常用任务模板，需先开始对话 |
| `/template delete 名称` | 删除保存的模板，需先开始对话 |
| `/template run 名称 [本次补充要求]` | 运行模板明确指定的输入，不自动附加最近附件 |
| `/template batch 名称 完整批次编号 [本次补充要求]` | 用已确认、未使用的批次运行模板 |

处理收到的附件时，先发 `/batch show 完整编号` 核对文件，再发 `/batch seal 完整编号` 确认，最后发 `/template batch 周报 完整批次编号 本次按项目分组`。普通 `run` 不会把“最近收到的附件”自动当成输入；附件与模板指令分开发送。保存、删除和运行需先开始对话，待机或收尾时不执行，指令不用带 `/cc`。

完整句“按周报模板运行”可在后面加本次要求。“按周报模板处理这份表”“按周报模板处理这批附件”只在本人恰好有一个已确认、未使用批次时绑定；没有时先核对并确认，有多个时用完整编号指定。这里保存的“任务模板”是四项要求，批次的 `/batch template` 标记的是文件清单中的格式模板，两者可以一起使用。

入队时固定模板名、版本、定义及检查条件；之后修改或删除模板不影响已排队任务，`/resume` 也保留原版本、检查条件及绑定文件清单。模板任务只可用 `/queue cancel` 取消或 `/queue move` 调序，不能 `/queue edit` 改正文。输出目录在入队时按当前工作目录解析并固定，执行前再次核对；可写“工作目录”“工作目录/周报”、相对路径或工作目录内的绝对路径。不切换工作目录，越界或非法路径时不会调用模型，之后切换目录也不会悄悄改写已排队任务的目标。任务记录的“输入与模板”页签显示模板名、版本和四项要求，“检查结果”页签显示检查条件和结论。完整说明见 [功能改进：任务模板](../features/功能改进-任务模板.md)。

列表和操作回执中的下一步指令已填好完整编号并独占一行，可直接复制；标注需要任务说明或新正文的指令，仍需填写要求。任务完成的文字回复在全文成功缓存后附上本次任务的 `/result` 指令，无文件产物时也能直接查看；缓存失败仍发送结果正文并提示保存失败，不提供无法保证可用的查看指令。文件发送成功不会因本地快照清理失败改报失败，后台后续启动会尝试回收明确登记、未被活动任务占用的副本。普通、模板和批次任务共用最近约 200 条的终态记录保留规则，未完成、可恢复和结果未确认记录继续保留；结果文字仍保留 7 天。元数据清理不删除原附件或产物。

## 开关

日常双击 **`微信助手.bat`** 打开托盘运行中心。关闭窗口只隐藏，菜单“退出程序”才停止后台；重启和退出会检查是否有任务或附件未完成。

微信发“开始对话”唤醒，发“结束对话”收尾后待机。完全退出后微信不能唤醒，需在电脑上重新打开助手或等下次登录自启动。

兼容入口 `微信开关.bat` 会直接启停后台，`toggle.ps1 -Off` 会强制终止进程树；日常请使用运行中心。只想查询或启动可用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\desktop\toggle.ps1 -Status
powershell -NoProfile -ExecutionPolicy Bypass -File .\desktop\toggle.ps1 -On
```

未开机或后台已退出时不会处理消息；重新启动后只能拉取微信服务端仍保留的消息。任务恢复规则见文末。

看到“代码已更新，重启后生效”时，先等当前任务、队列和附件处理完成，再点运行中心的“重启服务”。后台约每 60 秒检查一次已加载的 Python 源码；只修改或提交文档不会触发这个提示。

鼠标悬停在“服务维护”的说明文字或“重启服务”按钮上，可查看版本诊断和启动时提交号。“版本状态未知”表示版本证据不足，不表示已是最新版，也不等于微信连接故障。重启会加载当前磁盘代码；之后延迟加载的模块仍可能使版本状态变为未知，详见 [托盘运行中心说明](托盘运行中心说明.md)。

“重启服务”只重启后台。更新了托盘脚本时，等任务收尾后用菜单“退出程序”，再双击 `微信助手.bat`，才能同时重新加载托盘和后台；点窗口右上角关闭只会隐藏。

## 怎么说话

两种模式，随你挑。

**懒人模式（推荐连续聊的时候用）**：先发一句「开始对话」，之后直接说话就行，一个字都不用多打。聊完发「结束对话」。

```
你：开始对话
它：✅ 已进入对话模式
    （30 分钟不说话会自动退出，桥重启也会。）
    接下来直接说话就行，不用带 /cc。
    下面这些都能直接说：

    💬 直接说话：看一下 D 盘有哪些文件夹
    🎵 电脑：打开微信 · 下一首 · 大声点 · 音量调到30% · 锁屏
    📅 开会：进会 413231713 · 六点四十进会 413231713（到点先问你）
    🖥 屏幕：/see 看窗口能点什么 · /windows 开着哪些 · 看看画面（截图让它念）
    👆 点按钮：点一下开始播放（先问你要点哪儿，回「确认」才点）
    📁 文件：发给我 D:\报告\汇报.pptx
    📋 其它：/new 清上下文 · /apps 有哪些应用 · /meetings 定下的会 · /help 全部

    说「结束对话」退出；带 /cc 也照旧能用。
你：看一下 D:\CC Cliworkspace 里有什么
你：把桌面那个 xlsx 里 2 月份的数据挑出来，另存成一个新表
你：结束对话
```

> **上面那份「常用功能」清单就是这条回话的全部内容**，想换成你自己顺眼的就改
> `bridge_text.py` 里的 `CHAT_ON_TIPS`（纯文本常量，不用碰逻辑），改完重启开关就行。
> 完整版说明书是 `/help`（`bridge_text.HELP`），那份没变。

触发词不是一份写死的清单，而是**「动词 + 名词」的组合**（2026-09 改的）：

* 动词：开 = 开始 / 开启 / 进入 / **打开**；关 = 结束 / 停止 / 退出 / 关闭
* 名词：对话 / 聊天 / 会话，各自也能带「模式」（`进入聊天模式`、`打开对话模式` 都认）

所以「开始对话」「开启会话」「进入聊天模式」「打开对话」这类说法**全都是同一个意思，全都认**，`/on`、`/off`、`/chat`、`/end`、`持续对话`、`免前缀` 也认，前后带「帮我」「谢谢」这类客套没关系。

为什么改成组合：以前是一条条枚举，压根配不齐 —— 「对话模式」「会话模式」都收了，唯独漏了「聊天模式」，`打开对话` 也没收，一共十几种说法被**静默丢掉**，看着和桥挂了没什么区别。组合说的是同一件事，而且以后再加个名词只动一处。

但**光秃秃的「开始」「停止」不算**（单独发这两个词更像在说「接着刚才那件事」），`打开微信`、`打开文件`、`开始播放`、`退出登录` 这些动词对、名词不对的也一律不算 —— 它们照旧走原来的路（`打开微信` 还是开应用）。

不在对话模式、又忘了带 `/cc` 的时候，桥会回一句「🔕 这条我没执行：要让我干活得带上 /cc，或者发「开始对话」之后就不用带了」，同一个人 10 分钟内只提示一次（配置里 `no_prefix_hint_minutes`，设 0 就完全不提示）。提示里**不会带原消息的内容**，免得把口令这类东西回显出去；对话模式自动退出的那条通知也算一次提示，两条不会连着来。所以**再也不会出现「发了没反应、也不知道为什么」的情况**。

三件事值得记住：**空闲 30 分钟自动退出**（会主动发条微信告诉你，想改时长动 `config.json` 里的 `chat_mode.idle_minutes`，填 0 就永不自动退出）；**桥重启也会退出**，因为这个状态只在内存里；自动退出后你要是又发了句裸消息，它会明说「这条我没执行」，不会装死。

**前缀模式（默认）**：干活的消息带 `/cc`，这是防手滑用的——不带前缀就当闲聊，不会真去动你的文件。

```
/cc 看一下 D:\CC Cliworkspace 里有什么
/cc 把桌面那个 xlsx 里 2 月份的数据挑出来，另存成一个新表
/cc 刚才那个再加一列合计
```

对话模式下带 `/cc` 也不报错，两者不冲突。

最后这句能接着上一句，因为上下文是连着的（会话 ID 存在 `sessions.json`，重启也不断）。要开新话题就发 `/new`。

不过上下文有**保鲜期：隔 2 小时没说话，下一条就自动算新的一段**——第二天再发「刚才那个」它是接不上的，那种跨天追问本来也多半记错了对象。想改时长就动 `config.json` 里的 `context_ttl_minutes`（填 0 就是永不过期）；想彻底每条都从头开始，把 `keep_context` 改成 `false`，那样 `sessions.json` 里也不会留任何会话 ID。

注意对话模式和上下文保鲜期是**两件独立的事**：前者管「要不要打前缀」，后者管「还记不记得刚才说了什么」。默认一个 30 分钟一个 2 小时，所以通常是对话模式先退出。

不带前缀也认的内置指令：`开始对话`/`结束对话` 开关对话模式、`/new` 清上下文、`/where` 看工作目录、`/id` 看自己的用户 ID、`/apps` 看能开哪些应用、`/see` 看当前窗口上有什么能点、`/see 波点音乐` 把那个窗口切到前面再看、`/windows` 看现在开着哪些窗口、`/meetings` 看定下的会（`取消定时` 全部取消）、`看看画面` 截一张当前窗口的图让 Claude 念一遍上面有什么（花额度、画面会送出去）、**`/parse 一句话` 看这句话会走哪条通道**（不动手、不花额度，专门用来查「为什么它没反应」）、`/help` 看说明。

`/parse` 值得记住，它专治「我这么说它怎么不认」：把你要试的那句话原样写在后面，它按分发顺序把每个通道的判定打给你——

```
你：/parse 关闭电脑
它：🔍 这句话会怎么走（只看判定，不动手、不花额度）
    状态：不在对话模式 ｜ 没有待确认的点击

    免前缀那条链（不带 /cc 也认）
    · 看定下的会 / 取消定时：不认
    · 回上一条问话：不认
    · 回待确认的点击：不认
    · 对话模式开关：不认
    · 看看画面：不认

    要带 /cc 的那条链（在对话模式里也免前缀）
    · 进会：不认
    · 音量（调到/多少）：不认
    · 电源（锁屏/关机）：认（关机）
    · 开关应用/播放键：落回 Claude（解析成关闭「电脑」，但桌面上没有这个名字的图标）
    · 发文件：不认
    · 点一下：不认
    ...
    （第一条「认」就是会接走它的那条）
```

上面这个例子里，一眼就能看出「关闭电脑」为什么归电源而不归开关应用 —— 因为**两条都解析上了，是顺序决定的**。`/parse` 后面也可以不空格（`/parse关闭电脑`），`/解析`、`/why` 也都认。

语音也行——微信会把转写文字一并送过来，所以可以直接对着手机说「/cc 看看今天的日志」。你发来的图片和文件会在收件功能开启时下载保存；关闭时才会提示拿不到内容。也可以把电脑上的文件发回微信，具体见「你发来的图片和文件」和「让它把文件发到微信上」。

## 管桥自己：状态 / 日志 / 重读配置 / 队列 / 叫停

```
/status               桥活了多久、正在跑哪条（跑了多久）、后面排着几条、定下的会和提醒
/log                  把 bridge.log 的最后 30 行发过来（`/log 100`，最多 100 行）
/reload               改完 config.json 不用重启，就地重读
/queue                看排着哪些活儿（`/queue clear` 清掉排着的）
/queue cancel 编号    取消自己尚未开始的一条任务（完整 32 位编号）
/queue edit 编号 正文 修改自己的普通文字排队任务
/queue move 编号 N    调到你的第 N 条；从 1 开始
/stop                 叫停正在跑的那条（排着的不动）
/stopall              连排着的一起清
```

**这几条都不用带 `/cc`** —— 出问题的时候人正在着急，再让你打一遍前缀没有道理。

**`/status`** 是「它现在到底在干什么」的答案。以前这个问题只能走到电脑前看：

```
📊 桥的状态

已运行 3 小时 12 分（09:31 起的）
本进程收到 128 条消息
正在跑：把那个表处理一下（跑了 4 分 20 秒）
后面排着 2 条
定下的会 2 条 · 记下的提醒 3 条
对话模式：你在里面（还能免前缀 21 分钟）
日志：bridge.log 412 KB
```

**`/log`** 把 `bridge.log` 的尾巴发到微信上，排错不用再回电脑前。发之前会**抹掉凭据**：`bot_token` 和 `account_id` 按值抹，另外还认「`xxx@im.bot`」这种形状兜底（万一哪天有新东西被写进日志）。日志比 256 KB 大时只读尾部。

**`/reload`** 让改完的 `config.json` 当场生效，**不重启进程** —— 排队里的活儿、对话模式、上下文、定下的会，一个都不受影响。刻意做成「就地重读」而不是「让桥自己重启」：重启一旦失败（配置写错、零件拉不起来），你就只能走到电脑前，那和当初砍掉「远程解锁」是同一类风险。所以规矩是：

* **先把新的整份算一遍**，算成功了才一次换上。中间任何一步出错，**旧配置一个字都不动**，桥照旧干活；
* `config.json` 连 JSON 语法都不对、`workdir` 不存在、`claude_extra_args` 里塞了被禁的开关 —— 一律拒绝，并说清是哪儿不对；
* **白名单重载成空的、或者新白名单里没有你** —— 拒绝。那等于把你自己锁在门外，而 `/reload` 这条指令本身也在门外；
* 有活儿正在跑的时候拒绝（先 `/stop` 或等它跑完）；
* `bot_token` / `account_id` / `base_url` 换过了，会提醒你**这项要重新扫码登录才生效**，不假装已经生效。

**`/queue`** 列出自己的排队任务正文、完整编号和本人序号，其他用户只显示“另一个用户的任务”。单条取消、改正文和调序见上面的指令；只操作自己尚未开始的任务。`/queue clear` 仍清掉全机排着的任务，正在跑的那条不动。

**`/stop`** 叫停正在跑的那条 —— 把 `claude.exe` 那棵进程树一起杀掉（`taskkill /T`；不杀整棵树的话，`.cmd` 包装器会留下孤儿进程接着读写你的文件）。三件事要知道：

* 只收 `叫停`、`别跑了`、`取消任务`、`/stop` 这两三个明确说法，**光秃秃的「停」「停止」一律不动手** —— 那几个字在正常一句话里出现得太频繁，而认错一次就是把正在干的活儿杀掉；
* 叫停**不可逆**：它可能已经改过盘上的文件了，回话里会写明这一点；
* 排着的那几条默认不受影响（那是 `/stopall` 的事）。

顺带堵了个口子：单条最长能跑 `timeout_sec`（默认 600 秒），而队列原来是**无界**的 —— 连发十几条就会堆好几个小时，从微信这头看就像「发什么都没反应」。现在队列有上限（`config.json` 里的 `queue_max`，默认 20，填 0 = 不限），满了会直说「这条我没接」，而不是默默堆着。

## 开关电脑上的应用

```
/cc 打开波点音乐
/cc 启动一下剪映
/cc 关闭微信
/apps                 查看当前可直接打开的应用
```

这条路**不经过 Claude**：桥自己扫描桌面和开始菜单、校验启动目标、按名字匹配后启动，也不需要在电脑前点「允许」。代价是只认「打开/启动/运行/关闭 + 名字」这种句式。

范围为**桌面图标、开始菜单中的有效应用，以及系统中已安装的 Microsoft Edge**（`.lnk`/`.url`/`.exe`，桌面在 `C:\Users\your-name\Desktop`，自动从注册表读）。名字不用打全，`剪映` 能中 `剪映专业版`，`ccswitch` 能中 `CC Switch`；有两个像的（比如 `pdf` 同时像 PDFgear 和 PDF2Zh）会回来问你要哪个。常见应用名找不到有效启动项时会明确提示，不会猜成相似名字的助手或工具；其他未识别请求仍交给模型。卸载、帮助、启动文件夹和失效快捷方式不会从开始菜单加入列表。

几条边界：

- 只接受**名字**，不接受任何命令行参数——所以不存在「顺手拼一条别的命令」的空间。
- 关闭用的是普通关闭（`taskkill` 不带 `/F`），未存的东西还会弹保存框；有些程序会赖着不关，再说一次或者手动关。
- 系统进程和桥自己依赖的进程（explorer、python、claude.exe 等）一律拒关，即使桌面上真有指向它们的快捷方式。
- 新增应用后发 `/apps` 可刷新；同名不同程序会标为“名称（1）”“名称（2）”，按完整名称选择。

不想要这个功能：`config.json` 里 `app_launch.enable` 改 `false`；只想留「打开」不要「关闭」，就把 `allow_close` 改 `false`。自动找不到桌面的话，把桌面路径填进 `app_launch.extra_dirs`。

句首的客套和重试口气都不影响识别：`帮我打开X`、`再试一下打开X`、`你能不能打开X` 都认。

## 直接进腾讯会议

```
/cc 进会 413231713            拉起腾讯会议并直接入会
/cc 进会 413-231-713          带分隔符也认
/cc 打开腾讯会议 413231713     这么说也行
/cc #腾讯会议：413-231-713     腾讯那段邀请文案原样转过来也认（前面补个 /cc）
/cc 进会 413231713 密码 8888   有入会密码就这么带上
/cc 进会                      没给号，我回一句问你要号（不花额度）
```

走的是腾讯会议自己的协议链接 `wemeet://page/inmeeting?meeting_code=<号>`，和你在网页上点「加入会议」是同一条路：**不经过 Claude，1 秒就回，不用在电脑前点「允许」**。

几条要知道的：

- **两种说法都认**：① 自己打的短句，里面得有「进会 / 入会 / 加入会议 / 腾讯会议」这类词，再加一串 9 到 11 位的号；② 别人发来的**整段邀请文案原样转发**，靠的是里面 `#腾讯会议：413-231-713` 这个腾讯自己生成的标记（`会议号：413231713` 也认），所以那段里的链接、日期、时段都不影响。**光发一串数字不会进会**——手机号后 9 位、快递单号、验证码都可能撞上，而进会是有后果的动作（你会真的出现在别人的会里）。
- **号必须只有一串**。「进会 413231713 和 987654321」这种有两串的、以及连成一长串分不清断点的，都不猜，照旧交给 Claude。同一个号在邀请文案里出现两遍不算歧义。
- **否定和推迟不会误进会**：「别进 413231713」「明天进会 413231713」「进会 413231713 然后把纪要发我」「#腾讯会议：413231713 记到日程里」——这些都交给 Claude，它能问清楚，桥不能。代价是「特别」这种带「别」字的句子也会落回 Claude，多花一次额度而已。
- **麦克风和摄像头控制不了**，由腾讯会议自己的默认设置决定，进去自己确认一下。
- **入会密码那个参数名我没验证过**（腾讯没有公开文档）。拼进去了，客户端要是没接住会自己弹密码框让你手输，不会失败得很难看。真验出来不对，改 `config.json` 里 `meeting.password_param` 换个名字就行，不用改代码。
- 光一条会议链接（`https://meeting.tencent.com/dm/xxx`，没带 `#腾讯会议：` 那行）**还是不认**，会交给 Claude；转发整段邀请就没这个问题，因为标记在里面。
- 密码**不写日志**；会议号在默认配置下日志里也只留位数。

拉不起来一般是两种情况：腾讯会议没装，或者 `wemeet://` 协议没在系统里注册（手动开一次腾讯会议通常就注册上了）。这两种我会直接说「拉不起」，并让你先 `/cc 打开腾讯会议`。整个功能的开关是 `config.json` 的 `meeting.enable`。

### 到点再进（定时）

```
/cc 六点四十进会 413231713          到点我先发一条问你，回「确认」才进
/cc 18:40 进会 413231713            24 小时制也认
/cc 晚上八点半进腾讯会议 413231713
/cc 二十分钟后进会 413231713         「半小时后」「一个半小时后」也认
/cc 六点四十进腾讯会议，我把会议号发给你    先只记时间，下一条把号发来才算定上
/meetings                          看有哪些定下的会
取消定时                            全部取消（这句不用带 /cc）
```

**到点不会自己进**，它先给你发一条：

```
它：⏰ 到点了：18:40 那场会，会议号 853-329-165。
    回「确认」我就拉起腾讯会议，回「取消」就不进；5 分钟不回自动作废。
你：确认
它：⏳ 正在拉起腾讯会议，进 853-329-165。
```

几条要知道的：

- **时间只认当天**：钟点（「六点四十」「18:40」「下午三点」「晚上八点半」）和「N 分钟后 / N 小时后」。「明天八点」「后天」一律交给 Claude——跨天的会我不替你记。说的那个点今天已经过去了，我直接回一句「已经过去了」，**不会悄悄顺延到明天**（顺延过的时刻到点你早忘了）。
- **不写全的时刻按最晚那个理解**：「三点」在下午发过来算 15:00 而不是 03:00。要是那个点也过去了，回复里会把它按 15:00 报给你，好让你看出它是怎么理解的。
- **一次最多定 5 场**（`meeting.max_pending`），同一个号同一个点不会重复记。
- **定下的会落盘**（项目目录里的 `meetings.json`），所以 18:00 定 18:40 的会、中间关一次开关也还在。但**到点那一刻开关必须开着**——电脑睡了、开关关了就到不了点。重开之后要是**刚过去不到 10 分钟**（`meeting.late_minutes`），它会补问一次并告实话「晚了几分钟」；早过去了就只回一句「这条作废了」，不会把你拉进一场早开完的会。
- **「确认」这个词两头都在用**（点按钮那边也用它）。规矩是：明确说「进会」「不进」的一律归会议这边；光一个「确认」而且当时还有个待确认的点击，就让给点击。到点的问话一出现，之前那个待确认的点击就作废了——同一个字不能两头抢。
- **等号那一步只在内存里**：「六点四十进会，我把会议号发给你」记下的是时间，桥重启就忘了；号发过来定上之后才落盘。号那条也要带 `/cc`（或者在对话模式里）。
- `meetings.json` 里有会议号和入会密码（明文），所以它进了 `.gitignore`，也在「不发到微信」的名单里。
- 整个定时的开关是 `meeting.timer_enable`，等确认的时限是 `meeting.confirm_seconds`（默认 300 秒）。

这条路和立刻进会一样**不经过 Claude、不花额度**：定上、到点问、确认后拉起，全是桥自己做的。

## 定时提醒

```
/cc 明天九点提醒我交房租          到点我直接发一条微信给你
/cc 九点提醒我吃药               今天九点；已经过了就顺延到明天九点
/cc 20分钟后提醒我看锅            相对时间也认（「一个半小时后」也认）
/cc 后天下午三点提醒我开会         后天、大后天都认
/cc 每天早上九点提醒我吃药        「每天」= 会重复：到点发一条，然后自动排到第二天
看提醒                         看记下了哪些（不用带 /cc）
取消提醒                       全部取消（不用带 /cc）
取消提醒 2                     只取消第 2 条
```

**和进会、关机最大的区别是「顺延」——这是故意的，两边口径正好相反：**

* 进会、关机遇上「今天已经过了」只回一句「过去了」，**不替你顺延**（一场早开完的会、一个你想关机的时刻，过期就没意义了）。
* 提醒反过来：下午两点说「九点提醒我吃药」，你要的多半是**明天**九点。所以没说日子、今天那个点又都过了时，它**顺延到下一个还没到的时刻**（明早九点，不是明晚九点——取最近的那个），而且**回话里会把理解成的时刻写出来**：

```
你：/cc 九点提醒我吃药          （现在晚上十点半）
它：✅ 记下了：明天 09:00 提醒你「吃药」。
    （你说的那个点今天已经过了，我按明天记的——不对就重说一次。）
```

* 但**明说了日子的不滚**：「今晚九点提醒我吃药」说过了今天，过了就是过了，它直说「今天 21:00 已经过去了」。


**「每天」是唯一会重复的那种**（说「每天」「每日」「每一天」）：

```
你：/cc 每天早上九点提醒我吃药
它：✅ 记下了：每天 09:00 提醒你「吃药」——每天到点都会发，发完自动排到第二天，不用天天重说。
```

* 钟点**不随你现在几点说而变**：「每天九点」一律按 **09:00** 记（要说晚上就写「每天晚上九点」）。一次性提醒才靠「哪个还没到」来消歧，重复提醒描述的是一张固定的作息表。
* 到点发完**不删、排到下一天**，所以桥中途关过、隔几天再起来也**只补一次**，然后接着按原来的点往下走。
* 同一件事**换个钟点**（先说了「每天九点提醒我吃药」，又说「每天晚上八点半提醒我吃药」）：它**既不悄悄改掉旧的那条、也不记成两条**（两条会在两个钟点各响一次），而是告诉你已经有一条每天 09:00 的了、要怎么改。要早上晚上各一条，就把内容说得不一样（写成「早上吃药」「晚上吃药」）。
* 「每天」以外的周期**一律不做**，整句交给 Claude 问：「每周一」「每星期」，还有「每个工作日」「每月1号」这种（日历口径不一样，做不对就会在你没想到的那天响）。
* 自相矛盾的也不认：「每天10分钟后提醒我」「每天明天九点提醒我」。

几条要知道的：

* **到点直接发，不用回「确认」**（进会那条才要确认——它是有后果的动作）。提醒没有后果，错过它才是真损失。
* **到点那一刻开关得开着、电脑别睡**，否则到不了点。不过错过也不作废：**晚一点照发**，只是在正文里写明「晚了 X 分钟」；只有超过 `remind.stale_hours`（默认 24 小时）才只说明一句、不再报内容（一条三天前的提醒打扰你没意义）。
* **最多同时记 10 条**（`remind.max_pending`），**只认 7 天以内**（更远的说「太远了」）。
* 时间是**复用进会那套解析**的，所以「晚上八点半」「22:00」「23:30」这些写法一律一样；但**「10天后」这种「日子+天」的写法不认**（交回 Claude），要跨多天请说「大后天」或「200小时后」。
* 要同时有**时刻**和**「提醒我」这类词**才算提醒，所以「提醒功能怎么用」这种问句不会被吞掉，照旧交给 Claude。
* `reminders.json` 里装的是你要提醒自己的事（往往挺私人），所以它和 `meetings.json` 一个待遇：进了 `.gitignore`，也在「不发到微信」的名单里。
* 整个开关是 `config.json` 的 `remind.enable`。

这条路**不经过 Claude、不花额度**：记下、到点发，全是桥自己做的。

### 到点跑一句话（定时任务，2026-09-27 加的）

```
/cc 明天九点帮我跑：把那个表处理一下     到点我把这句话交给 Claude 真去跑
/cc 每天九点帮我跑一下备份               「每天」也认：每天到点跑一次
看任务 / 取消任务                        和「看提醒 / 取消提醒」是同一份清单、同一条路
```

**它和提醒共用一张表**（`reminders.json`）：同一个计时线程、同一条「看清单 / 取消」的路，`/status` 里也一起数。区别只在到点干什么：

| | 到点做什么 | 花额度吗 | 太旧了（超过 `remind.stale_hours`） |
| --- | --- | --- | --- |
| 提醒 | 发一条微信给你 | 不 | **照发**，只在正文里写「晚了多久」 |
| 定时任务 | 把那句话交给 Claude 跑 | **花** | **不跑**，只说明一句它作废了 |

几条要知道的：

- **这是「真去执行」**：到点等于你自己发了那条消息——会花额度，也可能改盘上的文件。所以定的时候回话里会写明这一点，到点也会先回一句「开始跑了」再动手。
- **晚太久就不跑了**（和提醒刻意不同）：一条三天前的指令现在执行很可能是错的，宁可让你再说一次。
- **前面排满了不会丢**：队列入不进去时会排到一分钟后再试，并回你一句。
- 词表是硬规矩：**必须说「帮我跑 / 找到点跑 / 定时跑 / 帮我执行」这类**，光说「跑一下」不认——「我明天九点要跑一下步」说的是你自己。问办法的（「怎么定时跑一个脚本」）也一律交给 Claude。
- 想让某句话到点跑、又不想花额度，那就用**提醒**（「明天九点提醒我交房租」）；反过来，想让它「到点替我干这件事」才用这条。

## 开完之后让它放歌

```
/cc 打开波点音乐并开始播放      开应用，等 6 秒，按播放键
/cc 下一首                    也可以单独说，不用先开应用
/cc 暂停
/cc 上一首
/cc 停止播放
```

按的是**键盘上的媒体键**，和电脑上真有那几个键一样：谁在放音就归谁，所以不需要看见界面。要知道的三件事：

- **播放和暂停是同一个键**，本来在放的时候说「播放」会把它停掉。
- **键给谁不由我定**：浏览器里正播着视频的话，「下一首」可能切的是那个视频。
- **搜某首歌、切歌单做不到**，那得真的看见界面并点，走下一节那条路。音量单独一节，见下面。

「开完等 6 秒」是因为应用刚起来还接不住按键。等完按了没反应（起得慢），再说一句「播放」就行。秒数在 `config.json` 的 `media_control.open_delay_seconds`，整个功能的开关是 `media_control.enable`。

「继续」「开始」这两个词故意没收进来——单独发过去更像是在跟 Claude 说「接着刚才那件事」。要按播放就说「播放」或「继续播放」。

## 控制电脑音量

```
/cc 大声点            系统音量 +10%（「音量调大」「声音大一点」都认）
/cc 小声点            -10%
/cc 静音 / 取消静音
/cc 音量调到30%       直接设到某个值（「音量最大」「音量一半」也认）
/cc 音量多少          现在是多少
/cc 打开波点音乐并大声点   也能和开应用连着说
```

管的是**系统主音量**（右下角那个喇叭），不是某个应用自己的音量——这点和播放键不同，播放键归最近放音的那个应用。

有**两条路**，桥自己选，你不用管：

- **音量键**（一定能用）：和键盘上的音量键一样，一下 2%，所以「大声点」是连按 5 下。这条路**读不到当前是多少**，所以回话里只会说「已按 5 下，一共约 +10%」。
- **系统混音器**（能用就用）：直接读写系统音量，于是回话会带具体数字（「系统音量：40% → 50%」），也**真的分得清静音和取消静音**（会告诉你「本来就没静音」）。第一次用要 1~3 秒（要现编一段 C#），这几秒桥收不到新消息。

**混音器那条路挂了会自动退回音量键**，功能不会因此没了——回话里有没有具体数字，就是走了哪条路的标志。但「音量调到 30%」和「音量多少」**只有混音器做得到**：按键那条路连当前值都读不到，算不出该按几下，所以它宁可回一句「读不到系统混音器」，也不会瞎按。

一次调多少在 `media_control.volume_step_percent`（默认 10%，会被凑到 2 的整数倍）；混音器那条路的开关是 `media_control.absolute_volume`。

**故意不认的说法**：光说「大点」「小点」「音量」「声音」不动手（更可能在说字号、图片，或者只是提了一嘴）；「30 分钟后把音量调好」里的 30 不当音量看；一句话里出现两个数字（「音量从 30 调到 50」）也不猜。这些都落回 Claude。


## 屏幕亮度

```
/cc 亮度调到50%       直接设到某个值（「亮度拉满」「亮度一半」「亮度最低」也认）
/cc 亮度多少          现在是多少
/cc 屏幕亮一点        调亮一格（默认 10%）；「屏幕太亮了」「屏幕暗一点」同理
```

走的是 Windows 自己的 WMI 背光接口，**只管笔记本内屏**：外接显示器是另一套协议（DDC/CI），各家型号五花八门，这条不做。一次调用约 1 秒。

几条要知道的：

- **下限留在 5%**：说「亮度调到 0%」它也停在 5%，回话里会写明「你说的是 0%，屏幕实际落在 5%」。理由很实在——屏幕全黑的时候你还在手机那头，什么都看不见了。
- **回话里的数字是「设完再读回来」的那个**，不是我们以为设成的那个（「屏幕亮度：90% → 50%」）。屏幕要是没接住就直说「没动」。
- 和音量一样**没有按键兜底**：读不到就照实说读不到，不假装调过了。整块的开关是 `brightness.enable`，「亮一点」一格多少是 `brightness.step_percent`（默认 10）。

**故意不认的说法**：光说「调到50%」不认（可能在说音量、缩放、进度条）；「亮度调到 30 分钟后」不认（那是时间）；一句话里两个数字（「亮度从 30 调到 50」）不猜；「屏幕分辨率多少」「屏幕截图发我」这些虽然带「屏幕」，但不归这里。这些都落回 Claude。

## 关机、锁屏

```
/cc 锁屏              锁上屏幕（「把电脑锁上」「锁一下」也认）
/cc 电脑锁了吗         现在锁没锁
/cc 关机              默认留 1 分钟再关
/cc 十分钟后关机       相对时间（秒 / 分钟 / 小时，「半小时后」「一个半小时后」都认）
/cc 晚上十点关机       钟点也行（「22点关机」「十点半关机」「23:30 关机」都认）
/cc 取消关机           定下的关机在到点前说这句都能拦住
/cc 睡眠              进睡眠（待机）；唤醒按一下电源键或键盘
/cc 休眠              写进硬盘再断电（powercfg /h off 的机器上会说不能休眠）
```

这两件事的门槛不一样，先分清：

- **锁屏**开箱就能用，一句系统调用，不用配置也不用额外权限。**但锁上之后只能你自己到电脑前开**，见下面那一段。
- **关机**也开箱能用，但它是这套东西里**唯一不可逆的动作**。所以默认不是立刻关，而是留 60 秒——这点时间够回话发到你手机上，也够你反悔。说了具体时间就按你说的来，但再急也至少留 10 秒（回话得先发得出去），再久也不超过 24 小时（这是**我们自己**定的上限，口径和定时进会一致：只管今天之内。`shutdown.exe` 自己能吃到十年）。
- **到点是强制关，不会弹窗问你「有未保存的文件，要不要继续」。** 这不是我们选的：`shutdown /?` 里写着 `/t` 大于 0 时隐含 `/f`，而这里的等待时间永远大于 0。定时关机多半在你不在电脑前的时候到点，所以这句要紧——真有没存的东西，别指望它拦一下。

**关于钟点**（2026-09-03 加的）：

- 只认**今天之内**的点。「明天十点关机」不认，会原样交给 Claude——顺延过的时刻到点你早忘了，不如让你再说一遍。
- 说的那个点今天已经过去了（正午说「早上八点关机」），它**不定、也不顺延**，回你一句「今天的 08:00 已经过去了」。
- 没说上下午的按**晚的那个**算：中午说「9点关机」定的是 21:00。但回话里一定会把理解成的点写出来（「已安排 21:00 关机（还有 9 小时）」），看错了立刻说「取消关机」。
- 光说「定时关机」不给时间，它会回一句「时间呢」而不是按默认 60 秒关——那两句话在人嘴里不是一个意思。

**睡眠和休眠（2026-09-27 加的）**：说「睡眠」就进待机（本机是 S0 低电量待机），说「休眠」就写进硬盘再断电。两件都比关机温和，但**都是「人得回电脑前动一下」的动作**——手机上叫不醒它，所以单独有个开关 `power_control.allow_sleep`。几条要紧的：

- **回话先发出去，8 秒后才真的睡**。当场睡的话那句「✅ 好，电脑这就睡了」永远发不出去，你那边只看见「说完没反应」——和关机留 60 秒是同一个理由。
- **动手之前先问 `powercfg /a` 这台机器能不能睡**：本机就只有「待机(S0)」和「休眠」，没有 S3，别的机器还可能把休眠关了（`powercfg /h off`）。不能睡就直说，绝不假装睡了。
- **「我要睡了」不会被误认**——那句说的是你自己。靠的是「摘掉关键词之后剩下的必须是空的」：词表里只有「睡眠/休眠/待机/睡一觉」这种带宾语的写法，问句（「休眠和睡眠有什么区别」）和办法（「怎么让电脑睡眠」）也一律落回 Claude。
- 睡眠走的是 `SetSuspendState`，**不是**网上那条 `rundll32 powrprof.dll,SetSuspendState 0,1,0`：开着休眠的机器上那条会真休眠下去，而「睡眠」（秒醒）和「休眠」（掉电也还在）是两件事。

**没有「定时开机」这回事**（2026-09-03 确认的）。关掉之后桥自己也没在跑，没有任何软件叫得醒这台电脑——能叫醒它的只有 BIOS 里的定时开机和局域网里另一台设备发的唤醒包，都在这套东西之外。想要「早上自己醒过来」只能走**休眠**而不是关机，那条路要动 BIOS 和计划任务，而且这台机器上还没验过，细节写在 `部署指南.md` 的「定时开机为什么没有」。顺带一句：**休眠不用担心桥**——进程被冻住而不是杀掉，醒来接着跑，中间的消息微信那边替你排着。

**远程解锁没有了**（2026-09-03 砍掉的，连那个装脚本 `install_unlock.ps1` 和 SYSTEM 计划任务一起删了；老的说明里要是还写着「说解锁我用 PIN 开回来」，那是过期的）。锁屏界面画在**另一张桌面**上（Winlogon），只有 SYSTEM 身份的进程碰得到，桥自己怎么按键都落不到那儿去；绕过去的唯一办法是装一个以 SYSTEM 跑的计划任务，再把 Windows PIN 加密存在硬盘上——那等于把「能以你的身份跑代码」升级成「能开你这台锁着的电脑」，而真机上试了三轮，那张安全桌面始终不接手键盘。收益抵不上这份风险，于是整块拿掉。现在说「解锁」会被当成普通消息交给 Claude，它顶多告诉你怎么解锁，不会真去开。**所以远程锁屏之前想清楚：你不在电脑前的话，这台机器就一直锁到你回去。**

几件要知道的事：

- **「取消关机」里含着「关机」**，「电脑锁了吗」里既有「锁」又有「电脑」。所以顺序是定死的：先看是不是取消关机 → 再看是不是问状态 → 锁屏 → 最后才是关机。每一对都有专门的用例卡着。
- **「解锁」那类说法一句都不会被误当成锁屏。** 靠的是「认出关键词之后剩下的必须是空的」这条规矩：「解锁屏幕」摘掉「锁屏幕」还剩个「解」，就不算数。自测里把这一批钉着。
- **这条路不经过 Claude**，不花额度，也不用等模型。

**故意不认的说法**（一律落回 Claude）：「关闭电脑上的微信」——这句里就有「关闭电脑」，只看包含关系等于替你关机；「怎么关机」「关机快捷键是什么」「屏保和锁屏有什么区别」这类在问办法的；带日子的（「明天十点关机」「周一十点关机」）和问句式的（「几点关机」「十点前关机」）；带路径、链接、文件后缀的（「把 `D:\a.py` 里的关机代码删掉」）；超过 24 个字的长句。规矩是**认出关键词之后，剩下的部分必须是空的**（关机允许剩一个时间）。

不想要关机就把 `config.json` 里 `power_control.allow_shutdown` 改成 `false`；整块的开关是 `power_control.enable`。锁屏一直留着，它不需要任何配置。

## 让它看窗口、点按钮（点之前一定问你）

```
/see                      当前窗口叫什么、上面有哪些能点的东西
/see 波点音乐              把这个窗口切到前面，再看它上面有什么
/windows                  现在开着哪些窗口
/cc 点一下开始播放          找到它 → 先告诉你要点哪儿 → 你回「确认」才点
/cc 双击 我喜欢的音乐
```

流程固定是**两步**，中间那句确认不用带 `/cc`：

```
你：/cc 点一下开始播放
我：👆 打算点「开始播放」（波点音乐 · 按钮 · 屏幕 450,320）。
    回「确认」我就点，回「取消」作废；180 秒不回就自动作废。
你：确认
我：✅ 点了「开始播放」（450,320）。要看结果就发 /see。
```

有好几个像的会摆出来让你挑，**回数字就等于确认**：
```
我：⚠️ 有 2 个像「播放」的：
    1 播放全部（按钮）
    2 播放列表（列表项）
    回数字我就点那个（回数字就等于确认），回「取消」作废；180 秒不回自动作废。
你：2
```

看的只是**当前在最前面的那个窗口**。你不在电脑前的时候，最前面往往是桌面（`/see` 会直说「现在最前面是桌面」并把开着的窗口列给你），这时候发 `/see 波点音乐`——它会**先把那个窗口切到前面**再看。所以远程操作的标准动作是：

```
/cc 打开波点音乐     →  /see 波点音乐     →  /cc 点一下<看到的真名>  →  确认
```

`/see` 走的是 Windows 的控件树，**不截图、不上传任何画面**，也不花额度，1 秒就回。

**看不到东西的时候，注意它说的是哪一种「空」**——四句话对应不同的下一步：

- 「读控件树这一步本身失败了：…」= 探测没查成，不是窗口里没东西。在电脑上跑 `python app\wechat_bridge.py probe 波点音乐`，它会把 PowerShell 的原始报错打出来。
- 「控件树里只有一块画布（FLUTTERVIEW）」= 这个应用（波点音乐就是）用 Flutter 写的，整个界面就是一块画布，按钮一个都没告诉系统。控件树这条路对它无效，只能看图。
- 「摸到 57 个节点，但没有一个是带名字、可见、有大小的可点控件」= 这界面是自己画的，连名字都不报，同样只能看图。
- 「控件树一个节点都没有」= 这个窗口完全不参与 Windows 的控件体系（游戏、部分播放器），也是看图。

微信和波点音乐这类自绘应用，正常按钮一个都报不出来，所以列出来的名字后面可能跟一句「从自绘控件里翻出来的，不一定准」——那批是从文字、图片这些非按钮控件里翻的，点下去不一定是你想的那个东西，不对就改说「看看画面」。

### 控件树没用的时候：「看看画面」

```
看看画面        截一张当前窗口的图，让 Claude 念一遍上面有什么（不用带 /cc）
```

它只**念**，不点、也不给坐标：一句话说这是什么界面、正在显示什么，然后列出画面上看起来能点的东西的名字。念完你再说「`/cc` 点一下<它念到的名字>」，那一步会再看一次图算坐标，点之前照旧要你回「确认」。所以 Flutter 这类应用上的完整动作是四步：

```
/cc 打开波点音乐  →  /see 波点音乐  →  看看画面  →  /cc 点一下<它念到的名字>  →  确认
```

代价必须知道：**慢、花掉一次额度、而且会把当前窗口的画面送到模型服务端**（回复里也会先说一句再去做）。所以前台是桌面、窗口最小化、终端类窗口、或者 `screen_control.vision_fallback` 是 `false` 这四种情况下它 1 秒就回你「不行」，不会先白花一次额度。画面描述用的是一个一次性会话，不会混进你正常的上下文；说了「看看画面」也会作废之前那次待确认的点击。

几条要知道的：

- **它只会点你说的那一下**，不会自己连着点第二下、也不会顺手做别的。每一次点击都要重新说、重新确认。
- **说了别的事，待确认的那次点击就作废了**——免得过一会儿一句「好」把它点了。
- **确认的那一刻会重新核对窗口**：窗口换了、被挪过位置或改过大小，一律不点，让你重说一次。存的是绝对屏幕坐标，窗口一动就等于在乱点。
- **终端、注册表、组策略、任务管理器、UAC 弹窗这类窗口上一律不点**。终端里点一下等于替你按回车执行一条命令。要加别的窗口进黑名单，写到 `config.json` 的 `screen_control.refuse_titles`。
- **`/see <名字>` 切窗口有时会失败。** Windows 有前台锁，后台程序抢前台经常被系统拒掉，这时它会如实回「系统没让它到最前面」，不假装成功——过几秒再发一次，或者回电脑上点那个窗口一下。
- **控件树里找不到才会截图**（游戏、部分播放器是自己画界面的，控件树是空的）。那一步慢一些、**会花掉一次额度**、而且**会把当前窗口的画面送到模型服务端**——所以回复里会先说一句再去做，坐标也只是猜的，可能偏几十像素。不想要这条退路就把 `screen_control.vision_fallback` 改 `false`。
- **截图只留最近 1 张**（`screen_control.keep_shots`），在项目目录的 `shots/` 里，已经加进 `.gitignore`。窗口画面里可能有聊天记录或密码框，不该一直堆着。
- 整个功能的开关是 `screen_control.enable`，确认时限是 `confirm_seconds`（默认 180 秒）。
- **坐标体系对不上的时候它宁可不点。** 缩放不是 100% 的机器上，如果进程没能设成 DPI 感知，读到的窗口坐标和鼠标用的坐标就不是一套，点下去会整体偏掉——这种情况它会直接拒绝并说明原因，而不是碰运气按一下。8 月 29 日真机上就出过这一次（截出来的图偏到窗口外面、内容还被放大了），已经修掉，现在多了这道自查。

找不到某个东西的时候，先发 `/see` 看它在控件树里到底叫什么名字，照那个名字说。名字不用打全，能对上开头或者包含就行。

## 让它把文件发到微信上

```
/cc 发给我 D:\报告\汇报.pptx        路径打得出来就这么说，最快
/cc 发给我桌面上那个汇报的 ppt       说不清路径就这么说，它去找，找到就发
/cc 把刚才写的那个 md 发给我
```

说法很宽：「发给我」「发我」「传给我」「发到微信」「发过来」都认，放句首句尾都行（`/file <路径>` 也认），前后带「帮我」「谢谢」这类客套没关系。**要带 `/cc`**（或者在对话模式里），和「打开 XX」一个规矩。

两条路的区别值得知道，因为花不花额度不一样：

- **路径写全了**（`D:\...` 或 `/...` 开头）而且文件真的在：桥自己加密上传，**1 秒回一句「📎 正在传」，不经过 Claude、不花额度**。传完文件就作为一个文件出现在这个对话里，手机上直接点开。
- **说得含糊**（「桌面那个汇报的」）或者路径写错了：那句话照旧交给 Claude，它去找，找到之后在回复末尾偷偷写一行标记，桥把那行摘掉、把文件传上去。这条路**花一次额度**，慢一些，但你不用打路径。

传的是**原文件本身**，不是转成图片或文字，所以 pptx、xlsx、docx、zip、pdf 都行。传输过程是加密的（AES-128，密钥随消息一起走），文件会经过腾讯的 CDN——这和你自己在微信里发文件是同一条路。

不发的东西（这几条是硬拦，不看你怎么说）：

- **文件夹**——只能发单个文件，要整个目录先让它打包成 zip 再发那个 zip。
- **看着像密钥或凭据的**：`.pem` `.key` `.pfx` `.p12` `.ppk` `.jks` `.kdbx` 后缀，以及 `.env`、`id_rsa`、`.netrc`、`.git-credentials`、`credentials.json` 这类名字。真要发就自己复制一份改个名。
- **桥自己的 `config.json`、`sessions.json`、`meetings.json`** 等——`config.json` 里有 `bot_token`，发出去等于把这个机器人交给别人；`meetings.json` 里有会议号和入会密码。
- **超过 20 MB 的**，以及 **0 字节的空文件**。20 MB 是我自己定的保守上限（微信那边真正的上限没有公开文档），要调就动 `config.json` 里 `send_file.max_mb`。
- **不在它能碰的范围里的**（也就是 D 盘之外）——先复制到 D 盘。

一次最多发 3 个文件（`send_file.max_per_reply`）。整个功能的开关是 `send_file.enable`，改成 `false` 之后它只会告诉你路径。

大文件要等：加密是纯 Python 做的，实测大约 1.5 MB/秒，一个 3 MB 的 pptx 大概 2 秒，20 MB 的要十四五秒，再加上传时间（你发来的文件解密也是这个速度）。这段时间桥照常收别的消息。

## 你发来的图片和文件

你发**图片**或**文件**给它，它会自己收下来：

- 存在 `D:\微信bot文件夹` 里，回话里告诉你存成了什么名字；
- 文件名前面带时间戳（防重名），原名保留在后面，比如
  `20260926-125301-表.xlsx`；
- 单个文件最大 **20 MB**，超了它会直说不收（这个数在 `config.json` 的 `inbox.max_mb`）；
- **只存不动**：不执行、不自动打开、不解压。

想让它看/处理，就接着说一句，比如「看看刚发的那张表」「把刚发的图里的字念出来」——
它会自己读那个文件（那个文件夹本来就在它能读的范围里）。

总容量默认上限 **1 GB**（`inbox.quota_mb`）。满了**不会自己删**，会先问你一句：

> ⚠ 收件夹快满了（上限 1.0 GB，现在 1.0 GB），要收这条得先腾出 12.3 MB。
> 要删掉的是最老的 2 个（都丢回收站，能找回来）：
>    20260812-101500-旧表.xlsx（12.0 MB，46 天前）
> 回「删掉」我就删了再收这条；回「不删」我就当没收。

- 回 **「删掉」/「删吧」** → 清掉最老的那几个（**丢回收站，能找回**），然后接着把你这条收下来；
- 回 **「不删」** → 这条不收；**5 分钟**不回也当没收（都不会删东西）；
- 只删**它自己收下来的**、而且确实在那个文件夹里的文件——你自己放进去的东西它不碰；
- 光说「确认」不算（那个字是别的两件事在用的）。

## 它回话的排版（2026-09 改的）

微信里能看见的就是那几行字，所以「好看」只等于**排版**。这一版动了三处，全是纯文案，不碰任何解析：

**① 回话带状态记号**，一眼看得出成没成：

| 记号 | 意思 | 什么时候出现 |
| --- | --- | --- |
| ✅ | 办成了 | 已按下、已锁屏、已安排关机、已记下、进了对话模式、点了那一下 |
| ⏳ | 还在做 | 还在跑、排队、正在传文件、正在拉起腾讯会议、要去截图了 |
| ❌ | 没办成 | 拉不起、本地文件不可读、超时、功能关着、名字找不到、窗口对不上 |
| 🔕 | 无需动作 / 这条没执行 | 没带 `/cc`、对话模式刚自动退出、待确认的点击作废了、本来就已经是那个状态（例如音量已经在最大、本来就没安排关机） |
| ⚠️ | 要你挑一个 | 应用名或控件名有歧义，摆出候选让你回数字 |
| 👆 | 等你确认 | 「打算点哪儿」，回「确认」才真动手 |
| ⏰ | 到点了 | 定时进会那条问话 |
| 📎 | 文件 | 正在传本机的文件 |
| ⏱ | 用时 | 超过 20 秒的任务，末尾单独一行 |
| ⏹ | 被你叫停 | `/stop` 拦下了正在跑的那条（和 ❌ 分开：一个是你自己喊停的，一个是它没干成） |

**② 长回复的分片换成中文括号**：以前是 `[1/3]`，现在头一片是 `（1/3）`，最后一片是 `（3/3 · 完）`——手机上「后面还有没有」一眼就知道。

**③ 给 Claude 的排版规范**（写在 `config.json` 的 `prompt_prefix` 里，每次问它都带一遍）：结论放第一行；一句话一行；超过三行就分点；不要 Markdown 表格和代码块围栏；路径、命令各自单独一行；要说的事超过三百字就写进文件、回复里只给路径。**想改风格就改这一段，不用动代码。**

顺带修掉一个隐患：中文 Windows 的控制台是 GBK，打不出 emoji 会直接抛 `UnicodeEncodeError`。现在 `bridge_config.make_console_safe()` 把控制台输出的编码错误降级成「替换」（那个窗口里显示成 `?`），`bridge.log` 那条路本来就是 UTF-8，不受影响。

## 用着顺手的几个习惯

**长东西让它写成文件，别让它在微信里念。** 手机上看几千字很痛苦，而且超过 1800 字会被切成 `（1/3）`、最后一条带 `（3/3 · 完）` 这样好几条。说「写到 C:\WeChatBot\workspace\xxx.md」，回你一句路径就行，回电脑前再看；急着现在看就接一句「发给我」，它会把文件传到这个对话里。

**任务是排队串行的**，一次跑一条，后发的等前面跑完。跑得久的会先出「正在输入」，超过 30 秒补一句「还在跑」，超过 20 秒的任务回复里会带用时。默认 10 分钟超时，超了中止。

**每条 `/cc` 都是一次完整的 CLI 会话**，消耗你的订阅额度，别拿它当搜索框用。对话模式下这一点更要留神：进去之后随口一句「嗯」也会真的跑一次 Claude，所以聊完记得说「结束对话」，别指望那 30 分钟的自动退出替你把关。

**产物登记不会自动传回文件**；完成后可发 `/artifacts latest` 查看清单，再用 `/getfile 任务编号 序号` 取回，或说完整句“把刚才的产物发给我”。先“开始对话”才能取回；未登记的文件仍可说“发给我 <路径>”。

## 它现在能碰哪些文件

整个 **D 盘**都能读写（`workdir` 是 `C:\WeChatBot\workspace`，另外配了 `--add-dir D:\`）。C 盘不在范围内。

`D:\安装位置` 是**只读**的——那底下是已装软件，包括本机 Python 和 Claude 自己依赖的东西。这条是写在 `prompt_prefix` 里的禁令，属于提示层面的约束，**不是操作系统级的硬拦截**。所以真正危险的批量删除类指令，还是别从微信上发。

这套东西等于把命令行开放给了你那个微信账号：拿到你微信的人就能读写 D 盘**、也能把 D 盘上的文件取走**（发文件这条路让这一点更直接了，所以上面那几条硬拦是必要的，但它们只挡凭据类文件，挡不住「把某个正常文件要走」）。真正挡人的是 `config.json` 里的 `allowed_user_ids` 白名单，`/cc` 前缀不是安全措施——它防的是你自己手滑，防不住别人。对话模式把这层防手滑也去掉了，所以白名单是唯一的一道门，别指望别的。不想要这个模式就把 `chat_mode.enable` 改成 `false`；不想让文件能被取走就把 `send_file.enable` 改成 `false`。它现在还能关机、还能锁屏——那两件事的边界写在「关机、锁屏」那一节里，尤其是「锁上之后只能自己到电脑前开」这句，别跳过。`config.json` 里有 `bot_token`，别提交 git、别丢同步网盘。

## 出问题先看哪儿

日志 `bridge.log`，在项目目录里。

日志**默认不记你发的内容**，只记「谁发的、几个字、跑了多久」。想看清某条消息为什么没触发，把 `config.json` 里 `log_message_text` 改成 `true`，排查完记得改回来。例外是 `-DebugLog`：那个模式会把收发的原始 JSON 整条写进日志，正文自然也在里面，所以平时别开着它。

日志会**自己滚**：`bridge.log` 写到 5 MB 就换一份，旧的存成 `bridge.log.1`，最多留 2 份，再旧的自动删掉——所以最多占 15 MB，不用手动清。想让它留得更少就把 `config.json` 里 `log_max_mb` 或 `log_backup_count` 调小（`log_backup_count` 填 0 就是一份都不留旧的）。要立刻清空：先双击 `微信开关.bat` 关掉桥，删 `bridge.log*`，再开。

## 重启与结果确认的边界

- 尚未被桥接收的消息依赖微信服务端保留和投递，不能承诺永久不丢。
- 执行队列仍在内存；新版普通文字任务会先保存待执行正文，重启后只有确认未开始的任务可通过 `/tasks` 中的 `/resume` 手动恢复。附件、屏幕操作及文件发送不提供此恢复入口，所有任务均不自动重跑。
- 收消息游标表示已经分发，不表示执行完成。已保留的任务记录按用户、消息和任务类型阻止重复接收；即时控制及已清理记录不享有完整持久化去重，不能承诺所有操作恰好执行一次。
- 重启前先用 `/status` 和 `/queue` 查看任务。异常重启后先检查文件或应用的实际状态，再决定是否重新发送，尤其不要直接重复文件修改、关机等操作。
- 应用启动只能确认系统调用未报错，回复为“已请求打开”；会议链接拉起不等于成功入会。文件发送成功表示服务端接口接受附件，不代表手机已下载或已读。
- 会话、定时会议和提醒各有自己的持久化规则；普通任务是否可恢复，以 `/tasks` 中的状态和恢复入口为准。


## 自动收尾与任务记录

“结束对话”或窗口“进入待机”会立刻停止接收新任务和新附件，已接收的队列与下载继续处理，完成后自动转为蓝色待机。期间可用 `/stop`、`/stopall` 取消普通任务，或说“开始对话”继续接收任务；已有提醒保持原规则。重启与彻底退出仍会拒绝中断忙碌任务。

发 `/tasks`（也可说“任务记录”“最近任务”）查看自己的最近任务，待机时也可查看。窗口最近动态下方显示本机任务记录。记录从本次升级后开始，覆盖 Claude 队列任务、文件发送、屏幕分析和附件接收；即时音量/开关应用等同步动作不在这一版记录范围内。

任务记录保存于配置 `task_journal_file` 指定的 `.runtime/tasks.sqlite`，存用户标识、消息标识、任务摘要、状态与时间。为支持手动恢复，新接收的普通文字任务会暂存交给 Claude 的完整任务正文；开始执行或取消时清空正文列。不保存微信登录令牌、回复凭据、原始消息对象或附件内容。正文可能包含用户自己的私人信息，请按本地工作数据保管数据库；清空字段不等于磁盘安全擦除。保留最近约 200 条已结束记录，待恢复和结果不确定的记录不自动删除；该数据库不允许作为附件发送。

重启后，新版保存了正文且尚未开始的普通文字任务显示“未开始，可手动恢复”。先说“开始对话”，再从 `/tasks` 复制 `/resume 任务编号`，即可重新排队；队列满时保留恢复资格，同一任务不能重复恢复，其他用户不能恢复你的任务。恢复使用当前配置、当前 Claude 会话和新消息的回复通道，不保证重现旧会话环境。已开始、等待确认及旧版没有正文的任务仍标为“结果不确定”，需要检查实际结果后重新发送。附件接收显示“已中断，请检查后重新发送”，屏幕点击、截图及文件发送不提供恢复入口。所有任务都不会自动重跑。完成状态表示处理流程结束，不等于外部应用效果已逐项核实。

托盘窗口隐藏时每 5 秒刷新，显示时每 1 秒刷新；提交控制操作时临时加快刷新。桌面、窗口和托盘统一为双对话气泡。运行中心标题、状态点和托盘图标以蓝灰色表示待机，以绿色表示已唤醒；右上角“微信已连接”独立表示连接正常，待机时也保持绿色。


## 故障说明、固定记忆与任务进度

- 主界面显示易懂的故障原因与建议：加密连接中断、DNS 解析失败、服务器无响应、登录可能失效等。已经正常通信后，短暂中断（默认 30 秒内自愈）不升级为界面故障，恢复后也不播报；持续超过 30 秒才显示故障，超过 3 分钟显示红色，仍会按后台策略重试；恢复后清除当前故障。凭据被拒等需要人工处理的情况仍立即显示。重复同类网络错误不反复刷主界面，原始错误仍保留在本机日志。
- 点击窗口右上角或托盘菜单的“固定记忆”，可查看和编辑已有记忆，选择目录后添加为桌面、常用工作目录或默认输出目录，也可直接记录偏好。清空编辑区后仍需点“保存记忆”才生效；关闭时提醒未保存内容。
- 保存会检测其他程序是否改过原文件，防止覆盖；内容上限 12000 字符，采用同目录临时文件替换。保存后下一次 Claude 调用读取新内容，当前任务不受影响。不要填写密码、令牌或密钥。它是模型参考信息，不会自动扩大文件访问权限，也不会自动修改系统目录。
- 当前配置 `task_progress: true`：普通任务先报告接收／排队，再报告开始处理；附件接收、文件上传有对应阶段提示。长任务首次到配置的 `progress_notice_seconds`（默认 30 秒）时提示当前阶段和已用时间，之后约每分钟更新，直到完成或停止。
- 窗口任务概览同步显示阶段。仅报告后台能确认的阶段，不编造进度百分比、预计完成时间或 Claude 内部正在读哪个文件。
- 固定记忆界面验证命令：`powershell -NoProfile -STA -ExecutionPolicy Bypass -File .\memory_editor.ps1 -Verify`，只操作临时测试文件，不修改真实记忆。

## 任务结果反馈

- 发文件：微信接口接受后，追加文件名、实际上传大小和本机来源路径的文字回执。该回执不表示手机已经下载或阅读文件。网络异常显示“未获得发送成功确认”，请先检查微信附件再决定是否重发；本地文件不存在或不可读则报告失败。
- 打开应用：保留“已请求打开，尚未确认窗口是否出现”，并给出 `/see 应用名` 查看入口。不会凭已有同名窗口就宣称本次启动成功。
- 停止任务：`/stop` 和托盘先报告“已请求停止”，执行线程退出后才报告“已叫停”；停止不回滚此前的文件改动。屏幕分析任务被取消也会正确记录为取消。
- Claude 返回非零退出码或明确的错误状态时，即使带有文字也按失败处理，保留错误说明；错误输出中的发文件标记不会触发上传。
- 普通文件处理的自由文本仍由模型提供；明确声明的任务产物会核对真实文件并做有限基础检查，普通文字路径不自动登记，文件内容正确性不在核验范围内。文件回执中的大小来自本次实际上传读取的数据。

## 一句话查看进度

发送“现在怎么样”“现在什么情况”“还在处理吗”“处理到哪了”“进度怎么样”或 `/brief`，可简短查看当前任务、已用时间、已知阶段、排队数量、附件接收数量和最近一条任务结果记录。可以带问号，也可带 `/cc` 前缀；待机或收尾期间也能查询，不会唤醒助手，不会延长对话或启动任务。

只展示自己的任务内容和历史；其他用户的当前任务仅显示“另一个用户的任务”。最近记录只表示处理状态，不声称文件或外部应用效果已经验证。有待检查或恢复的任务时会提示 `/tasks`。查询必须是一条完整的状态问句：例如“现在怎么样，帮我打开微信”不会被截成状态查询；带图片或文件的消息继续走原来的附件规则。原 `/status` 仍显示详细状态。

### 打开 Edge 浏览器

可直接说“打开edge浏览器”“打开 Edge”或“启动微软 Edge 浏览器”。即使桌面没有 Edge 图标，也会识别系统登记或固定目录中已安装的 Microsoft Edge，走本机应用启动通道，不需要模型执行 PowerShell。其他应用同时按桌面和开始菜单中的有效启动项匹配。

常用叫法：微信 → Weixin/WeChat 客户端，谷歌浏览器 → Google Chrome，PPT → PowerPoint，7zip → 7-Zip File Manager。微信助手需要明确说“打开微信助手”，不会被“打开微信”误选。

### 停止模型任务与附件传输

微信 `/stop` 或运行中心“停止当前任务”可停止模型执行、文件加密和上传，并阻止后续附件发送；`/stop` 保留后面的排队任务。界面显示“正在停止”，执行线程结束后再报告结果。

已发布的附件不能撤回；正在提交附件时取消会提示“送达尚未确认”，先看微信附件再决定是否重试。文件修改不会自动撤销。收件下载也支持取消：未完成文件会清理，已经保存的附件保留，后续分析不会再入队。

常见模型失败现在只显示一条简短原因与下一步，不再重复长篇权限错误；未确认的操作应先核对结果，避免重复执行。

### 收件取消和模型状态

- `/stop` 或运行中心“停止当前任务”：停止当前执行及当前接收的附件，保留已完成文件。
- `/stopall`：还会取消此前排队的附件接收；之后新发来的附件仍可正常接收。
- 如果临时文件清理失败，会明确提示检查收件夹，不会误报已经全部清理。
- 运行中心服务卡分别显示最近微信通信和模型状态。模型一栏根据实际任务更新，不自动消耗 API 额度探测；启动或切换后未调用时显示无记录。应用快捷启动不调用模型，也不会刷新这条记录。
- 模型已响应而本机工具缺少权限时，会区分为本机操作问题，不把它当成模型接口故障。

### 任务记录和常用应用

任务记录在运行中心“待处理事项”标题行的“全部记录”，常用应用在“常用入口”；托盘右键菜单也可打开（常用应用位于“设置”子菜单）：

- **任务记录**：查看现有任务账本的最近 200 条模型/附件任务，选择一条可看状态、结果摘要和关联文件；可定位本机文件所在文件夹。只有可恢复的未开始任务才提供复制 `/resume` 指令，不自动重跑。旧记录未保存过的详细结果显示为空。
- **常用应用**：勾选收藏，`/apps` 会先列常用项；选择应用可设置多个简称。点击保存后，下次名称匹配立即生效，不需要重启。别名不能包含命令/路径，也不能把“微信”“Chrome”等已有名称指到其他应用。失效项会显示不可用，不能通过旧别名启动。

当前不自动预设收藏，按自己的习惯勾选即可。任务摘要是限长记录，关联文件记录来自实际发送/接收，不保证列出模型在一次任务中创建的全部文件。
