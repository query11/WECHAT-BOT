# 真实阶段进度与界面记忆

本轮实现日期：2026-11-07。验证与加载情况见 [可靠性检查与验收](../testing/可靠性检查与验收.md)。

## 查看任务正在做什么

运行中心的“当前任务”区域增加当前阶段、总耗时和当前阶段耗时。后台实际进入对应操作时更新：

| 阶段 | 实际操作 |
| --- | --- |
| 准备任务 | 从队列取出任务，保存开始状态 |
| 接收附件 | 下载、解密和保存当前附件消息 |
| 核对输入 | 准备任务输入，核对并冻结批次文件 |
| 模型处理 | 正在调用模型处理任务或分析画面 |
| 检查结果 | 核验声明的产物文件，执行已配置的结果检查 |
| 发送回复 | 发送结果文字或加密上传文件 |
| 保存记录 | 保存任务最终状态和结果记录 |

鼠标悬停在当前阶段上，可查看实际经过的阶段。每个任务只显示实际进入的阶段；纯文件发送不会显示未执行的模型处理，接收附件与之后的处理任务分别计时。很短的阶段可能在两次界面刷新之间完成，经过记录仍能反映它。

耗时从任务真正出队或附件实际开始处理计算，不包括排队等待。采用单调时钟，系统对时不会让显示跳变。当前阶段连续上传多个文件时不会反复重置阶段耗时；没有数据时不显示百分比或剩余时间。

停止期间显示“正在停止”并保留当前阶段。任务结束或后台状态过期后清除旧计时；空闲时继续显示最近结果卡片。接收附件和模型任务同时进行时，当前任务优先显示，附件数量仍在底部。

## 自动记住界面习惯

运行中心、任务记录、任务模板、快捷任务四个窗口会记住窗口尺寸；含列表的窗口还会记住手动调整的列宽。任务记录会记住状态筛选和详情页签，快捷任务会记住上次页签。

偏好在调整后自动保存，关闭后重开或下次启动时恢复。窗口尺寸按逻辑像素保存，恢复时结合当前显示器缩放，并尽量限制在屏幕工作区内；窗口位置仍由程序安排。缩放、分辨率和小屏尺寸仍受窗口最低尺寸限制。

从“附件核对”“运行模板”“任务结果”等明确入口打开时，优先进入对应页签；直接启动快捷任务窗口时才恢复上次页签。重新打开不会恢复任务提交、预览确认或未保存的任务要求；搜索正文也不保存。

偏好独立保存在项目 `.runtime/ui-preferences/` 中，每个窗口一个 JSON 文件。文件损坏或不可读时使用默认布局；保存失败不阻断正常操作。需要恢复默认时，关闭对应窗口后删除其偏好文件即可，任务库、模板和后台配置不受影响。

python -X utf8 -m unittest tests.selftest_task_progress tests.selftest_experience tests.selftest_runtime
python -X utf8 tools/verify_workflow_ui.py --output .runtime/progress-memory-ui-check

验证使用隔离数据和模拟模型/传输，不运行真实模型任务或发送微信消息。四个窗口分别以独立进程保存和重开核对；额外检查损坏偏好回退、超大尺寸约束和指定入口页签优先。跨显示器切换及真实长任务的现场观察仍需实际使用确认。
