# 任务工作台与后续安排

本轮日期：2026-11-07。功能与 UI 同步推进，已完成任务工作台、结果继续修改、本机文件任务和定时任务管理。

## 第一轮：任务工作台（已实现）

- 顶部改为紧凑状态栏，保留连接状态、唤醒/待机、运行时长和最近通信。首页主要区域展示当前任务或最近结果，以及待处理事项；常用入口前移，模型与维护仍在右侧。
- 待处理事项汇总未结清的可恢复任务、结果不确定/中断、执行失败、文字发送未确认、结果检查未通过/未能检查，以及附件清单待确认或缺失项。同一任务的多个原因合并为一行。
- 正在执行或接收中的正常任务不计入待处理；人工结清后移出列表，原始任务记录保留。空清单、后台未启动、旧后台尚不支持和读取失败分别显示，读取失败不会被描述成“没有待处理事项”。
- 单击选择后点击具体操作，或双击/按 Enter，直接打开对应任务记录或附件批次。任务与附件按编号定位，不自动恢复、重试或确认；仍需在详情页明确操作。任务入口可定位超过最近 200 条的保留记录，附件入口可定位超过最近 10 批的未处理清单。
- 首页汇总当前白名单内的本机用户，最多展示最近 100 个事项，标题保留总数；超过上限时悬停标题可查看说明。处理后较早事项会继续显示。附件核对窗口自动选中该批次所属的微信用户，其他用户的数据不会混入当前视图。
- 最近结果按内容调整操作：有文件时保留文件打开/定位入口；没有文件时显示回复或失败说明入口。执行失败使用红色文字，检查待核对使用橙色，执行状态与检查结论继续分别表达。
- “最近动态”按钮可切换原动态列表，“返回待处理”切回清单；任务记录入口始终保留。没有固定模板时，“选择模板”直接进入已有模板选择流程。
- 首次打开默认尺寸为 960×720，已有尺寸偏好继续生效；最小逻辑尺寸仍为 880×640。

这些列表使用已有本地记录，不调用模型，也不发送微信消息。任务恢复、附件确认、文件打开继续使用已有执行入口和校验。

## 第二轮：结果继续修改（已实现）

从最近结果、任务结果或任务记录进入，选择文件或完整文字回复、填写要求并预览确认。提交时保存旧版本副本，生成独立结果目录和关联任务；配套版本列表、旧版本详情及手动恢复。范围与边界见 [结果继续修改](功能改进-结果继续修改.md)。

## 第三轮：拖入文件创建任务（已实现）

运行中心和托盘新增“文件任务”。拖入或选择本机文件、选模板或填写要求，选择文件留在本机或同时发微信，核对用户、输入与输出目录后确认。提交时保存输入副本，支持历史详情和重启后的手动恢复。范围与边界见 [本机文件任务](功能改进-本机文件任务.md)。

## 第四轮：定时任务管理（已实现）

运行中心、托盘和快捷任务新增“定时任务”。支持一次性/每天重复的微信提醒与自动任务，预览确认后保存；可编辑、暂停、恢复和删除，查看下次执行及最近触发，并直接打开实际任务记录。范围与边界见 [定时任务管理](功能改进-定时任务.md)。

## 后续方向（未实现）
