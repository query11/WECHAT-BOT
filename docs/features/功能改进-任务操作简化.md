# 附件对话与桌面任务操作

本轮实现日期：2026-11-07。功能需后台重新加载后生效；任务记录窗口需关闭后重新打开。验证与加载情况以 [可靠性检查与验收](../testing/可靠性检查与验收.md) 顶部为准。

## 连续对话处理附件

先在微信发送“开始对话”，再依次操作：

1. 发“接下来这几份文件一起处理”，或“开始收集附件 本周材料”。
2. 逐份发送附件，等待接收完成；此时只保存文件。
3. 发“发完了，合并这些表格”，或“发完了，按周报模板整理”。周报模板须事先保存。
4. 助手列出文件清单、任务要求；核对后发“确认执行这批附件”。

确认在 15 分钟内有效。清单预览后又收到文件、附件仍在下载、清单被修改或存在未处理的失败记录时，不会直接执行，需重新核对。模板定义和输出目录在预览时固定，之后修改或删除模板不替换这次任务的要求。

队列满时保留这份待确认任务，可在有效期内再次确认；已经入队的批次不会重复执行。“取消本次附件处理”取消正在收集或待确认的批次，已保存文件保留。上述操作都需助手处于唤醒状态，指令与附件分开发送。

原 `/batch` 指令继续可用。未指定批次的自然语言只采用本人的正在收集批次、当前待确认批次，或唯一可执行批次；没有明确对象时会提示，不猜测其他清单。

## 补救未确认批次

新收附件批次中，成功文件会保留。某条消息接收失败时，可以重新发送其中缺失的文件，核对清单后复制该失败记录附带的 `/batch dismiss 完整批次编号 失败记录编号`，移除这一条失败提示。它表示用户已处理或决定放弃缺失项，不表示后台自动重试成功；原失败接收记录仍保留在数据库中防止重复收件。

一条微信消息可能包含多个附件，因此失败编号对应接收记录。只补传缺失的文件，避免重复发送已经成功的部分。

选错了已保存文件，可发 `/batch remove 完整批次编号 附件序号` 将其移出清单，再上传正确文件。移除后序号会重新排列，需重新查看清单。磁盘原文件不会删除。

两种修改仅允许在未确认、没有进行中下载的批次内执行，且会使之前的确认预览失效。已经确认或绑定任务的批次不可修改。

`/batch recent` 仍严格固定所选的最近收件，后来的上传不会加入；最近收件准备失败时，应核对后取消并重新建立清单。补传收集流程适用于通过 `new` 或自然语言开始收集的新附件批次。

## 桌面任务记录

从运行中心打开“任务记录”：

- 搜索任务名称、编号或摘要，并筛选全部、需要处理、等待执行、正在处理或已结束任务。筛选范围为最近读取的最多 200 条记录。
- “需要处理”包含未恢复、结果不确定、接收中断、执行失败、文字发送未确认，以及结果检查未通过或未能检查的未结清任务。
- 选中任务后，支持直接取消排队、恢复未开始任务、标记已人工核对、放弃恢复和归档。正文补发及文件取回继续提供微信指令。
- 恢复使用后台本次启动后记住的该用户微信回复通道。没有通道、待机或正在收尾时，先在微信发“开始对话”。恢复后的结果仍发送给原任务用户。
- 窗口刷新在后台读取，期间保留旧列表。失败时提供重试，操作不自动重发。点击执行时后台重新检查任务所属用户、当前状态和任务库来源。

旧后台没有声明支持直接操作时，按钮禁用；重启后台加载新版后刷新即可。任务详情仍为只读，只有主动点击“恢复这条任务”“取消排队”等具体操作按钮才提交操作；暂不能执行时直接说明原因。新增的模板窗口与详情页签见 [模板窗口与任务详情](功能改进-模板窗口与任务详情.md)。
