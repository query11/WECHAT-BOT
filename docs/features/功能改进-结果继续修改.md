# 基于结果继续修改

2026-11-07 完成第二轮功能与 UI 改进。可从已结束任务的结果发起新的修改任务，并查看同一来源的版本记录。

## 使用步骤

1. 在运行中心“最近结果”、快捷任务“任务结果”或“任务记录”中点击 **继续修改**。
2. 选择结果文件，或切换为“修改完整文字回复”，填写本次要求，例如“压缩到一页，保留数据和结论”。
3. 点击 **核对本次修改**，查看来源、选择的文件、修改要求和新结果位置。此时不会执行任务或生成副本。
4. 点击 **确认修改**。系统重新核对来源版本，保存旧版本副本，再提交一个独立任务。完成后通过所选用户现有的微信通道返回结果。
5. 重新读取后，左侧版本记录会显示新任务；任务结束后可选中它并点击“以此版本继续修改”。排队中、执行中和待恢复的版本不能作为修改来源。

修改要求、文件选择、模式或来源变化后，都需要重新核对。预览有效期为 15 分钟；后台重启后需要重新预览。提交前仍要求所选用户已唤醒并具有可用的微信回复通道。

## 版本与文件

- 文件必须是原任务已登记并通过核验的产物。预览和确认都会核对路径、大小、时间与内容指纹；原文件已移动、删除或变化时停止提交，不悄悄改用其他资料。
- 每次选择 1–12 个文件，单文件不超过 20 MB，总量不超过 100 MB。文字模式使用完整回复缓存，最多 24,000 字；普通回复缓存仍保留 7 天，过期后可使用有效的结果文件。
- 确认后在工作目录下建立 `修订结果/<任务编号>/旧版本/` 与 `修订结果/<任务编号>/结果/`。副本使用编号文件名，原文件名称保存在任务记录中。
- 执行前再次检查已保存副本，并生成本次临时输入。之后原结果的变化不影响本次输入；副本本身被改动时停止执行。新产物登记和文件交付限定在本次结果目录。
- 任务记录“输入与模板”页可查看上个版本、最初任务、修改要求和输出目录；文件列表可定位旧版本副本。
- 修改家族的任务关联和已保存副本持续保留，不受普通历史 200 条清理规则影响，也不会随 7 天回复缓存一起删除。多次修改会增加磁盘占用，目前没有自动删除版本功能；有待恢复任务时应保留其副本。

## 运行与边界

重复确认同一预览只提交一次。若提交结果无法确认，界面提示先查任务记录，不自动重试。队列已经满时不会创建副本；并发入队或写盘出错仍可能留下保留目录，可按任务记录核对。

后台重启后，尚未开始的修改任务可手动恢复，并继续使用保存的副本。已经开始但结果不确定的任务沿用现有人工核对流程。取消仍使用原任务取消入口。

新任务只传入本次修改要求和明确选择的输入副本，不重新分派原任务的应用控制指令。模型提示要求保留输入、另存新结果；产物与交付检查可限制登记和发送范围，但不是对模型全部文件操作的系统级隔离。此轮未增加内容差异比较、自动回滚或模型写入沙箱。
