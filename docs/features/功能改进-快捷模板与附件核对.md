# 常用模板、附件核对与结果卡片

本轮实现日期：2026-11-07。验证与后台加载情况见 [可靠性检查与验收](../testing/可靠性检查与验收.md)。

## 常用模板快捷运行

运行中心“常用入口”新增模板选择框和“运行模板”。首次没有固定模板时，也可直接点击“运行模板”进入快捷任务窗口：

1. 选择微信用户和模板，点击“固定到运行中心”。每位用户最多固定 5 个；重新打开或重启后保留。取消固定不会删除模板。
2. 选择本次输入：按模板明确指定的输入处理，或使用一批已经核对确认的附件。不会自动附加最近收到的文件。
3. 填写本次补充要求，点击“核对本次任务”。检查模板版本、实际输出位置、输出格式、检查条件和输入清单。
4. 点击“确认运行”。需要先在微信说“开始对话”，让所选用户处于唤醒状态并建立回复通道。结果仍发送给该微信用户。

核对页面固定当时的模板版本和输出位置，确认有效期为 15 分钟；后来修改或删除模板不会替换这次已预览的要求。修改输入选择、补充要求、切换用户或重新读取后，需重新核对。后台重启、工作目录变化、附件被其他任务使用时，旧确认不能执行。相同确认重复提交只会入队一次。

保存和修改模板仍从运行中心右上角“任务模板”进入，详见 [模板窗口与任务详情](功能改进-模板窗口与任务详情.md)。固定模板与运行前核对不调用模型；只有确认运行后才加入任务队列。

## 附件批次核对

点击运行中心或托盘菜单的“附件核对”。窗口显示所选用户最近 10 个批次：

- 已收到的文件：文件名、大小及是否作为格式模板。
- 仍在接收的附件消息：显示数量，完成后点击“重新读取”。尚未落盘的消息不编造文件名。
- 失败或中断记录：显示失败编号及已有错误说明。

未确认且没有进行中下载的批次，可选中文件“移出清单”。磁盘原文件保留；移除后编号可能变化，窗口会重新读取。若在别处修改了清单，旧窗口的操作会被拒绝，防止误删另一项。

有缺失项时，在微信补传缺失文件，重新读取并核对后，选中失败记录点击“已处理缺失项”。这表示已补齐或决定放弃缺失项，不代表自动重试成功；接收记录保留。只有没有进行中下载、没有未处理失败且至少有一份文件，才能“确认附件清单”。

确认只固定清单，不立即运行模型。随后在“运行模板”页选用这批附件，或按原微信批次指令执行。已经确认或使用的清单不可再编辑。

## 任务完成结果卡片

运行中心在无当前任务、无排队和无附件处理时，将“当前任务”区域切换为“最近结果”，集中显示结果摘要、执行状态和内容检查结论。任务开始后自动恢复当前任务状态。

选择一个交付文件后，可点击“打开文件”或“打开文件夹”；“全部结果”和托盘“任务结果”打开所选用户的最近结果列表，查看文件清单及仍在保留期内的完整回复。

文件不存在时按钮禁用；直接打开支持常见文档、表格、图片和 PDF 等格式，其他类型可定位文件夹。这里打开的是磁盘上的当前文件；清单中的核验说明反映任务记录时的检查，文件后来发生改变时不能把旧结论当成重新检查的结果。

“处理结束”与“已配置的结果检查通过”分别显示。没有配置检查、检查未通过或未能检查都会明确说明。普通关联路径不会被标成已核验产物；无文件任务仍可查看文字回复。

## 验证入口

```powershell
python -X utf8 -m unittest tests.selftest_desktop_workflow
python -X utf8 tools/verify_workflow_ui.py --output .runtime/quick-tasks-ui-check
powershell -NoProfile -STA -ExecutionPolicy Bypass -File desktop\tray_app.ps1 -VerifyUX
python -X utf8 tools/verify.py --suite offline
```

窗口验证使用临时任务库、合成文件和模拟模型/传输，不发送微信测试消息，不启动真实模型任务。实际微信收发、文档默认打开应用以及跨显示器缩放仍由实机操作确认。
