# 常用任务模板：保存要求，按固定版本运行

把重复使用的输入要求、处理步骤、输出目录和格式保存为模板，也可以附上明确的结果检查条件。运行时只补充本次要求；需要处理附件时，先确认文件批次，再把该批次绑定到模板任务。操作从微信使用，运行中心与任务历史沿用现有布局。

原有四字段任务模板已有本机验证及后台加载记录；本轮新增的可选结果检查尚需后台加载后生效，本次未重启后台。手机操作、文件接收和结果检查回执仍待实测。本轮验证与加载状态统一见 [可靠性检查与验收](../testing/可靠性检查与验收.md)。

## 保存一个模板

先说“开始对话”，再将以下整段作为一条纯文字消息发送：

```text
/template save 周报
输入：已确认批次中的本周工作表
步骤：按项目汇总进展、问题和下周计划
保留原始事实，未提供的数据写“未提供”，不要补造
输出目录：工作目录/周报
输出格式：Markdown，包含进展、问题和下周计划三部分
```

`输入：`、`步骤：`、`输出目录：`、`输出格式：` 四个字段必须各自单独起一行，后续内容可以续行。可在四项之后追加第五个可选字段 `检查条件：`，每行写一条规则；不写时沿用原四字段行为。名称为 1 至 40 个字，不能含空格；每位用户最多保存 30 个模板，只能查看和管理自己的模板。

保存时校验检查条件的语法，不会调用模型、创建输出目录或处理文件。无效规则会拒绝保存；同名成功保存会覆盖当前定义，并递增版本。想保留两套同时可用的要求，应使用不同名称。

这里的“任务模板”是一组保存的要求。附件批次的 `/batch template 完整编号 N` 标记的是某个格式模板文件，例如空白报销表；两者可以一起使用，保存任务模板不会自动寻找或选择格式模板文件。

## 可选的结果检查

在模板的四项必填要求之后追加如下字段。文件名应与任务步骤要求交付的文件名一致；示例中的三条规则分别检查两份产物，实际使用只保留需要的规则：

```text
检查条件：
必需列 | 汇总.xlsx | 汇总 | 项目,金额
列合计 | 汇总.xlsx | 汇总 | 金额 | 1200.00
必需章节 | 周报.md | 进展,问题,下周计划
```

- `必需列 | 文件名 | 工作表 | 列名列表`：支持 CSV、XLSX；CSV 的工作表位置写 `-`，XLSX 写准确的工作表名。以表格首个非空行作为列名行，检查指定列是否存在。
- `列合计 | 文件名 | 工作表 | 金额列 | 预期合计`：支持 CSV、XLSX，使用十进制数精确合计指定列并与预期数值比较，不执行公式。目标金额列含公式时，即使文件带有计算缓存，也会报告未能检查，不能把缓存值当成本次计算结果。
- `必需章节 | 文件名 | 章节名列表`：支持 Markdown、TXT、DOCX。分别检查 Markdown 实际标题、TXT 独立整行、DOCX 标题样式段落；在普通正文中提到章节名不能替代标题。

可用半角 `|` 或全角 `｜` 分隔各段，列名与章节名用逗号分隔。检查条件总长最多 4000 字、最多 12 条规则；文件名只写含扩展名的名称，不写目录。规则精确匹配模型明确声明的产物文件名，不扫描输出目录或从回复中的普通路径猜测。多个产物同名时明确报告无法确定目标，不任意挑选一份。

每个被检查文件上限 10 MiB（10 × 1024 × 1024 字节），表格读取上限 20000 行、200 列。解析失败、格式不支持、超过检查限额等情况显示“未能检查”及原因，不计作通过；这些限额独立于产物基础核验和文件发送的大小上限。

完成回执及 `/artifacts 任务编号` 分别展示基础检查与结果检查。指定规则检查不通过或未能检查时，产物仍保留；只要原有基础核验和发送条件满足，仍可通过 `/getfile` 取回核对。检查不会自动重跑任务，也不改写原生成任务的执行终态；`/result`、`/resend` 保留原回执中的检查结论，不在查询或补发时重新检查文件。

检查通过只说明所列条件满足，不评价语义、事实、排版或完整业务正确性，也不证明手机能够打开文件。不配置条件的旧模板不追加这层检查，原行为保持不变。

## 文字任务与文件任务

文字材料或模板明确指定的输入可以用 `/template run 名称 [本次补充要求]`。例如已保存名为“会议纪要”的模板后，发 `/template run 会议纪要 本次会议文字如下：……`。也可以说完整句“按会议纪要模板运行 本次会议文字如下：……”。

普通 `run` 不自动附加最近收到的附件。模板的“输入”字段用于描述预期材料，不会替你确认哪份附件是本次输入；处理收到的附件应使用下面的批次流程。

1. 用 `/batch new 本周材料` 收集附件，或 `/batch recent N 本周材料` 固定已保存的最近 N 个收件登记项。
2. 接收完成后，用 `/batch show 完整编号` 核对实际文件清单；需要格式模板文件时，确认序号后用 `/batch template 完整编号 N` 标记。
3. 用 `/batch seal 完整编号` 确认清单固定。
4. 发 `/template batch 周报 完整批次编号 本次按项目分组`，将已确认、未使用的批次绑定到一条模板任务。

批次编号完整复制。待下载、下载失败或尚未确认的批次不能运行；同一批次仍只绑定一次任务。文件数量、大小、指纹核对和临时副本规则沿用 [附件批次说明](功能改进-附件批次.md)。

完整句“按周报模板处理这份表”或“按周报模板处理这批附件”仅在本人恰好有一个已确认、未使用批次时接受。没有可执行批次时先核对并确认；有多个时用 `/template batch` 带完整编号明确指定，不根据“这份”猜附件。

模板指令必须单独发纯文字消息，附件分开发送。保存、删除和运行需先“开始对话”，待机或收尾时不执行；查询待机也可用，所有指令不用带 `/cc`。

## 完整指令

| 指令 | 用途 |
| --- | --- |
| `/template` 或 `/template help` | 查看模板用法 |
| `/template save 名称` 后接四个必填字段及可选检查条件 | 新建或覆盖模板，并保存递增版本 |
| `/template list` | 查看自己保存的模板列表 |
| `/template show 名称` | 查看当前版本、四项要求与已配置的检查条件 |
| `/template delete 名称` | 删除当前保存的模板 |
| `/template run 名称 [本次补充要求]` | 运行模板明确指定的输入，不自动附加最近附件 |
| `/template batch 名称 完整批次编号 [本次补充要求]` | 按模板运行已确认、未使用的附件批次 |

`[本次补充要求]` 表示可选内容，不需要把方括号写进指令。模板依赖启用的任务记录库 `task_journal_file`；关闭记录库时不能保存、查询或运行模板。

## 输出目录

模板的输出目录在入队时按当前工作目录解析并固定到本次任务，执行前再次核对。可以填写：

- `工作目录`：当前工作目录本身。
- `工作目录/周报` 或 `周报`：当前工作目录下的子目录。
- 当前工作目录内的绝对路径。

模板不切换实际工作目录。输出目录越出当前工作目录或路径不合法时，任务会被拒绝，不会调用模型；先核对当前工作目录与模板字段，再重新保存或运行。保存模板时只是记录这项文本，入队时才解析并固定路径；之后切换工作目录不会悄悄改写已排队任务的目标，执行时若不再符合目录范围则拒绝执行。

输出格式也是保存的要求，例如 Markdown、XLSX 或 DOCX，不代表已生成文件或文件内容已核实。配置检查条件时，仅对声明产物执行指定规则。任务完成后仍用 `/artifacts 任务编号` 查看产物清单与检查结论，再用 `/getfile 任务编号 序号` 取回；文件发送接口确认不代表手机已经打开文件。

## 排队、修改与恢复

每条任务在入队时保存模板名、版本、四项定义及检查条件的快照；本次补充要求及绑定的批次清单也随任务保留。之后修改或删除模板，只影响后续新任务，不改变已经排队任务的要求或检查规则。

尚未开始的模板任务可以用 `/queue cancel 任务编号` 单条取消，或 `/queue move 任务编号 N` 调序；不能通过 `/queue edit` 修改正文。需要改变要求时，先取消原任务，再按新的模板或补充要求重新运行。

异常重启后，确认尚未开始的模板任务可沿用 `/resume 任务编号` 手动恢复，仍使用原模板版本、检查条件和原批次清单，不重新读取当前模板，也不从最近附件重新选择输入。已经开始的任务先核对实际文件与操作结果，不直接重放；所有任务都不会自动重跑。

单条取消模板批次任务仍不会让原批次重新可运行，后续处理需另建批次。停止或执行失败后，先检查可能已经产生的文件改动，再决定是否重新运行。

桌面任务历史在原详情区域追加模板名、版本和四项要求；有附件批次时同时展示固定输入清单。查看这些信息不触发执行或自动恢复，也不改变运行中心布局。
