# 拖入文件创建任务

2026-11-07 完成第三轮功能与 UI 改进。在电脑上直接选择资料，使用任务模板或填写处理要求，核对后加入原有任务队列。

## 从哪里开始

运行中心“常用入口”新增 **文件任务**，托盘菜单也提供同名入口。进入快捷任务窗口的“文件任务”页后：

1. 把文件拖到左侧蓝色区域或文件清单，也可以点击 **选择文件** 多选。重复路径自动忽略；选错时点击 **移出清单**。文件名称、大小和数量即时显示，悬停可看完整路径。
2. 选择已有模板，或保留“自定义任务”并填写要求。模板任务可补充本次要求；新结果会放入本次独立目录，模板原定义保持不变。
3. 选择结果去向，点击 **核对并预览**。预览首先显示接收结果的微信用户、结果去向与完整输出目录，下方列出任务要求、模板版本、检查条件和文件清单。
4. 点击 **确认创建任务**。系统再次核对文件版本，保存输入副本后排队。完成后可从“任务结果”或“任务记录”查看、打开文件，也可以继续修改结果。

更换文件、修改要求、切换模板或结果去向后，旧预览失效，需要重新核对。切换微信用户会清空本次文件和要求；草稿与确认令牌不保存到窗口偏好。预览有效期为 15 分钟，后台重启后重新预览。

## 两种结果去向

| 选择 | 本机文件 | 微信交付 |
| --- | --- | --- |
| 文件留在本机，摘要发微信（默认） | 新产物保存在本次结果目录 | 发送文字结果，不自动上传文件 |
| 文件留在本机，同时发送到微信 | 新产物保存在本次结果目录 | 发送文字结果，并上传本次登记且通过校验的新产物 |

两种模式都使用上方所选用户的现有微信回复通道，须先唤醒助手并在本次启动后建立可用通道。“文件留在本机”不表示完全离线，也不表示不调用当前模型。

文件交付由确认的选项决定，不跟随模型自行添加的发文件标记。发送新产物前重新核验文件版本；超出单次文件数量、大小或允许发送目录时，沿用现有机制明确报告未发送项，不声称全部完成。文件发送功能关闭时，可以选择默认模式。原始输入文件不会因为拖入而自动上传到微信。

## 输入、输出与恢复

- 每次 1–12 个本机非空文件，单个最多 20 MB，合计最多 100 MB。文件夹、网络/设备路径和网络映射盘暂不支持；路径重定向、凭据及助手运行数据继续受既有校验限制。
- 只按明确选中的文件路径读取，不扩展助手全局允许目录，也不追加最近微信附件。路径通过 JSON 输入传递，不拼接到 shell 命令中。
- 预览只检查，不创建任务、不复制文件。确认时再次核对大小、修改时间和内容指纹；任何一个文件变化或不可读，都先停止提交。
- 输入副本保存到 `工作目录/本机任务/<任务编号>/输入备份/`，新结果保存到同级 `结果/`。同名文件使用不同编号保存，原文件名仍记在任务中。
- 确认后原文件移动或变化不影响排队任务。执行前再次检查已保存副本，再生成临时输入；副本损坏时停止执行，不换用其他文件。
- 模板步骤、输出格式和检查条件按预览版本固定。此入口统一采用本次独立输出目录；核对页和任务详情均显示实际位置。
- 后台重启后，未开始的文件任务可手动恢复，仍使用保存的输入、模板版本和交付方式。已经开始但结果不确定的任务沿用原人工核对流程；取消仍使用现有入口。
- 任务记录“输入与模板”显示本次要求、去向与结果目录；文件列表可定位“本机输入副本”。结果可衔接上一轮“继续修改”。

任务副本和结果不自动删除，长期使用会增加磁盘占用；任务回执仍沿用现有历史保留规则。输入副本与新产物登记范围检查不构成对模型全部文件操作的系统沙箱。

## 验证

新增 `tests.selftest_desktop_files` 覆盖只读预览、单次确认、文件变化、输入副本、交付方式、同名文件、模板检查、用户与来源隔离、超限、重启恢复、取消及损坏记录。

`tools/verify_workflow_ui.py` 在隔离库和真实 Windows Forms 窗口中触发拖放事件，验证去重、目录拒绝、移出、模板/自定义预览、确认失效、提交一次、用户切换、输入详情和窗口偏好。没有调用真实模型或发送测试微信消息；资源管理器现场鼠标拖动与手机收件仍需实际使用确认。

完整回归和加载状态见 [可靠性检查与验收](../testing/可靠性检查与验收.md)，截图及证明在 `.runtime/local-files-20261107/`。
